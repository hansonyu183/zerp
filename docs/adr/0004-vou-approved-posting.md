# VOU 在审批时入账，最终处理表示业务完成

所有会产生业务台账流水的 VOU 单据统一在 `APPROVED` 时写入对应台账，并在 `unapprove` 时撤销对应台账流水；该规则覆盖库存、资金、往来、空桶等 LED 台账，不为不同账簿保留第二套入账时点。不会产生台账流水的单据只按各自履约规则维护完成状态。

`FINALIZED` 只表示单据所代表的业务已经完成，不承担入账或反入账。审批已经完成全部业务事实、没有后续履约步骤的末端单据，在审批和入账成功后于同一事务中自动进入 `FINALIZED`，不要求用户再次点击完成；用户反审时由服务端在同一事务中先重新打开再撤销入账。订单等存在后续履约的来源单据保持 `APPROVED`，根据下游已审批入账的数量或金额自动进入 `FINALIZED`；下游反审批导致不再满足履约条件时自动重新打开。系统不向用户提供 `finalize/unfinalize` 动作，也不保留人工完成补充路径。

自动完成或重新打开的审计主体记录为系统，同时保存触发单据、触发动作、发起用户和请求 ID，明确区分用户业务动作与系统派生状态。自动完成不要求用户拥有单独的完成权限。LED 期间结账只阻止会改变台账的 `approve/unapprove`，不得阻止不改变台账的自动完成或自动重新打开。

本次语义切换发生在真实生产数据进入系统之前，PAY 不建立例外。预览和演示环境中的旧语义测试数据直接重建或修正为当前语义，不引入切换检查器、历史回填 migration、兼容层或双写路径。切换完成后系统只保留 `APPROVED` 入账语义。
