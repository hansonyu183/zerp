# ACC 内部会计领域

## 1. 当前范围

ACC 负责 ZERP 的内部会计事实。本阶段只实现 Accounting Book（会计账簿）及人员访问范围；会计科目、期初、会计映射、自动记账、数量账和会计期间由后续规格逐步扩展。

ACC 不作为法定会计软件，也不提供科目流水、余额或其他面向用户的查询报表。

## 2. 会计账簿

每本会计账簿是一套独立核算范围，包含：

- 系统生成的 `bookId`；
- 系统按 `ACC-0001` 格式生成全局唯一且不可修改的 `code`；
- `name` 和可选说明；
- 格式为 `YYYY-MM` 且创建后不可修改的 `startMonth`；
- ISO 三字母 `baseCurrency` 元数据；
- 只读的 `controlBook` 标志；
- 乐观并发 `revision`。

账簿自身没有生命周期、启用状态或锁定状态。第一本账簿在创建事务内自动成为永久唯一的 Business Control Book（业务控制账簿）；调用方不能指定、切换或取消该标志。控制账簿不能删除，未被后续会计事实引用的非控制账簿可以删除。

基础币种当前仅作为账簿资料保存；ACC 不执行汇率、本位币折算或跨币种汇总。

## 3. 账簿访问范围

每个用户对每本账簿分别具有查询范围和操作范围，两种范围独立保存：

- 查询范围决定 `query` 和 `get` 是否能返回该账簿；
- 操作范围决定 `save` 和 `delete` 是否可以修改该账簿；
- HTTP 动作权限与账簿范围必须同时满足；
- 创建账簿的用户自动获得该账簿的查询和操作范围；
- 保存访问范围的用户保留保存前已经拥有的范围，不会因为执行保存而自动获得查询范围。

操作范围不会隐式扩大查询结果。需要从界面查看并操作账簿的用户必须同时获得两种范围。

## 4. HTTP 能力

ACC 使用 `POST application/json`、`/acc/book/{action}` 和统一业务响应包络，提供：

| 动作     | 行为                                                               |
| -------- | ------------------------------------------------------------------ |
| `query`  | 分页查询当前用户查询范围内的账簿                                   |
| `get`    | 读取查询范围内的账簿及访问范围                                     |
| `create` | 创建账簿；第一本自动成为控制账簿                                   |
| `save`   | 以 `revision` 修改资料和访问范围，不能修改编码、开始月份或控制标志 |
| `delete` | 删除未使用的非控制账簿                                             |

每个动作注册独立 APP 权限。OpenAPI 是 HTTP 字段和校验规则的唯一事实来源。

## 5. 验收边界

- 第一账簿在并发创建下仍是唯一控制账簿；
- 后续账簿永远不是控制账簿；
- 查询用户只能查询，操作用户只有取得查询范围后才会出现在查询结果；
- 范围外用户不能读取或修改账簿；
- 乐观并发和开始月份格式错误、手工编码等未知请求字段均在公开接口被拒绝。
