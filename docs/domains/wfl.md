# WFL 业务流程领域

## 1. 领域边界

WFL 是以 VOU 单据为节点的可配置流程引擎。VOU 仍独立负责单据正文、生命周期、附件和单据审计；WFL 只保存流程定义、实例、节点链接、分支执行结果和运行审计，不代理 VOU 权限或正文读取。

销售定价 `sale-pricing`、采购询价 `purchase-inquiry` 和其他收入 `other-income` 不进入流程目录，也不会触发或成为流程节点。

## 2. 流程定义

流程定义由一个根节点、若干下级节点和有向边组成：

- 每个节点绑定一种 VOU 单据实体；根节点无上级，其余节点必须且只能有一个上级。
- 一个节点可以配置多个下级，形成一对多分支；图必须连通且无环。
- 边指定来源单据到目标单据的转换器及条件；同一次批准事件中所有匹配分支都会执行，不采用互斥的“首个命中”。
- 定义和节点分别保存启动条件、分支条件、目标单据默认值及画布位置。
- 定义状态为 `DRAFT`、`ENABLED`、`DISABLED`。只有 `ENABLED` 定义接收新的根单据；停用不终止已运行实例。
- `code` 同时是流程类型和 API 实体段，创建后不可修改；`process-definition`、`process-instance` 为系统保留编码。`name` 是流程内容中显示的业务名称。
- 保存和状态切换使用 `revision` 乐观并发控制。已启用定义也可修改，修改只影响之后发生的批准事件，不回放既有事件。
- 启用前校验图结构、转换器兼容性以及转换器要求的默认值。未使用的草稿定义可以删除。

流程定义支持 `GRAPH` 和 `STARLARK` 两种来源。既有图形定义继续以结构化图为可编辑来源；新建流程默认使用 Starlark 脚本，脚本是草稿的唯一可编辑来源，节点图仅作为编译结果只读展示。Starlark 使用 `node`、`edge` 和 `workflow` 声明单根、单父、连通且无环的流程树，脚本可定义变量和辅助函数；保存时重新编译，并按稳定节点键保持节点标识。脚本草稿在发布能力完成前不得启用。手工试算源单使用 `{entity,data}` 结构，`data` 必须先通过对应根单据的 VOU 草稿契约校验；试算只记录通过的定义修订并返回规范化图的遍历轨迹，不创建流程实例、节点实例或 VOU 单据。

条件使用结构化 JSON DSL，支持头字段规则组 `all`、`any`，以及明细规则组 `lineAll`、`lineAny`。头字段包括 `entity`、`status`、`currency`、`businessDate`、`amount`；订单、出库、送货、签收和采购入库的产品明细字段包括 `productCode`、`unit`、`quantity`、`unitPrice`、`amount`，送货使用其来源出库明细；费用报销明细字段包括 `category`、`description`、`amount`。操作符为 `EQ`、`NE`、`GT`、`GTE`、`LT`、`LTE`、`IN`、`CONTAINS`。空对象表示无条件匹配。

## 3. 事件与原子性

WFL 只以 VOU 的 `APPROVED` 状态事件创建流程实例和下级单据，不订阅或推导额外的完成、重开或短结事件。

同一根单据可以同时匹配多个已启用定义，每个定义建立独立实例；单个定义的一对多分支可同时创建多个下级单据。实例、节点、边执行记录和自动单据均在触发批准的同一个数据库事务内写入，任何转换器、条件或写入失败都会回滚整个批准动作。

同一实例、来源节点和边只执行一次。多个流程需要同一来源与目标实体时复用已存在的自动下级单据，但分别记录各自的节点链接。

反批准时，系统删除由流程创建且仍为 `DRAFT`、revision 为 1、没有附件的直接下级单据，并清除对应边执行记录以允许再次批准。下级单据已编辑、已流转、带附件或并非系统创建时，反批准被拒绝。

## 4. 实例结构

实例只记录实际生成的节点、父子关系和运行审计，不维护实例完成状态、当前节点或完成进度。未命中的条件分支不会成为实例节点。

## 5. 首批转换器与费用付款

首批转换器包括：

- 销售订单 → 销售出库 → 销售送货 → 销售签收；
- 销售签收 → 往来收款-客户；
- 采购订单 → 采购入库 → 往来付款-供应商；
- 费用报销 → 费用付款。

物流平台、车辆、资金账户、经办人等无法从来源单据推导的字段由目标节点默认值提供。销售和采购原流程作为内置定义迁移；费用报销付款定义初始为草稿，配置资金账户后才能启用。

新费用报销单不再保存资金账户，也不直接产生资金流水。其批准事件可由流程生成费用付款草稿；费用付款保留来源报销、员工、金额和资金账户快照，批准后产生资金 `OUT`。迁移前费用报销保留 `LEGACY_DIRECT` 结算模式，继续按原规则直接出账。

## 6. API、权限与前端

流程定义 API 位于 `/wfl/process-definition/{query,get,create,save,trial,enable,disable,delete,catalog}`。`trial` 与保存共用操作权限，只允许试算已保存的 Starlark 草稿修订。每个已启用定义按其 `code` 提供 `/wfl/{code}/{query,get,audit-history}` 三个实例 API；`/wfl/process-instance/*` 提供全部流程实例的统一列表，并在“业务流程”下生成“流程实例”二级菜单。销售和采购流程的查询、详情与审计同样使用通用实例服务。

启用定义时事务性登记并启用上述三个 APP 权限，停用时禁用权限但保留普通角色的授权关联，重新启用后原授权继续生效。`superadmin` 按 APP 规则动态获得全部启用权限，不写逐项关联。登录和 session 恢复仍一次性返回 `permissions: string[]`，前端只从该数组中识别拥有 `query` 的统一流程实例入口和 WFL 流程类型并生成二级菜单，不提供或调用 menu 接口，也不额外查询流程定义。权限变更后前端强制恢复当前 session 来刷新权限数组。

流程定义页面对图形来源提供节点画布、拖拽位置、一对多分支、条件和默认值编辑；对 Starlark 来源提供脚本编辑、编译诊断、手工 JSON 试算和只读编译图。每个流程类型的二级页面共用实例列表、实际单据树和运行记录组件；列表返回根单据及往来单位快照，不返回流程状态、当前节点或完成进度。关键词只匹配流程内产品编码/名称与根单据往来单位编码/名称，往来单位筛选使用对象 ID 精确匹配。用户可查看实际单据树或打开根单据；单据正文仍由 `/vou/{entity}/get` 权限控制。

## 7. 验收边界

验收至少覆盖：多定义同时匹配、多分支同时命中、未命中分支、重复事件幂等、任一分支失败整体回滚、定义并发修改、编码不可修改和保留字冲突、启停权限及角色授权保留、动态 API 精确鉴权、停用不影响既有实例、反批准清理/阻断，以及费用报销到费用付款再到资金流水的完整链路。
