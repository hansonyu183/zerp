# 用户拼音受控回填

本流程用于 #378 隔离集成分支最终切换时，为既有用户填充统一拼音事实。它不表示已经执行生产转换或获得生产部署授权。新的隔离数据库直接使用当前 schema；普通请求和服务启动不隐式回填旧数据。

执行前按既有发布流程保存数据库备份并确认恢复方式，停止会修改用户名称或创建用户的旧 API 与初始化进程。通过受控环境注入 `TARGET_DATABASE_URL`，并按数据库边界设置 `TARGET_DATABASE_SCOPE`（`isolated` 或 `production`）；命令和日志不得打印连接串、密码摘要、用户资料、角色明细或审计原文。

1. 先运行 `pnpm --filter @zerp/api backfill:user-py`，仅检查基线并报告待回填数量，不修改结构或数据。
2. 核对目标库、备份与应用停写状态，取只读报告的 `users` 与 `factsSha256`，运行 `USER_PY_BACKFILL_APPLY=true USER_PY_BACKFILL_EXPECTED_USER_COUNT=<users> USER_PY_BACKFILL_EXPECTED_FACTS_SHA256=<factsSha256> pnpm --filter @zerp/api backfill:user-py`。实际事务基线必须与这两项一致；检查后发生的用户、角色关联或审计变化会使执行拒绝，不能跳过或自动换基线重试。
3. 保存命令的计数与校验摘要，核对完成报告；启动匹配新契约的 API，并通过用户查询及 Session 本人改名、管理员改名确认名称与拼音检索一致。

回填由服务拥有的单一事务执行，并使用事务锁阻止并发转换。缺少拼音列时先建立可回填列，使用与正常创建及改名相同的拼音规则填充，再校验持久化完整性。转换不得改变稳定 ID、账号编码、密码摘要、启用事实、revision、用户角色关联或既有审计；这些事实的前后校验必须一致。命令只输出计数和校验摘要，不输出受保护事实。重复执行应报告无待更新行，而不能制造新的业务修改或审计。

基线不符、计算或校验失败时整笔事务回滚，不绕过错误，也不在请求中补救。提交后的回读异常必须先调查真实状态，不自动重放。需要回退时恢复匹配的数据库备份与应用版本，不增加旧字段双写、旧路由或请求期兼容读取。 <!-- docs-check: legacy-exception=release-cutover ref=ADR-0052 -->

名称及查询语义由 [APP 用户](../domains/app.md#33-用户) 与 [APP 用户管理](../domains/app.md#55-用户管理) 拥有；回填与既有身份、关联、审计保留的真实数据库验证见 API 集成测试。
