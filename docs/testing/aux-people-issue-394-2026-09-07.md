# #394 经营主体与员工 AUX 验证记录

## 候选范围

经营主体与员工直接维护、临时编辑器、精确动作权限、旧入口删除、DCL/VOU/ACC/RPT 引用消费及一次性迁移。领域规则见 [AUX](../domains/aux.md#39-经营主体与员工)，操作边界见[迁移说明](https://github.com/hansonyu183/zerp/blob/c9c2d8fca30d9da7b4046315733b7666d564b0d5/docs/operations/aux-people-migration.md)。

## 实际验证

用户明确要求直接使用现有环境。本次复用已有 PostgreSQL，不调用隐式重建数据库的聚合命令，不创建隔离栈，不部署 API/Web。

- 真实数据库：AUX current 与迁移 3 项通过，包括当前资料转换、精确历史快照、权限映射和 blocker 回滚。
- 相关数据库回归：11 个文件共 26 项通过，覆盖 DCL 档案、仓库、VOU 快照/并发、ACC 期初、权限及 WFL/HTTP 协作。
- 员工重新启用补充回归：先观察到 `validation_failed`，修复保存快照与输入格式的转换后通过；启用不改写已保存的任职引用快照。
- Playwright：`aux-people.spec.ts` 通过，实际登录、菜单进入两页、新建/编辑/启停、员工四项引用选择、刷新丢弃未保存输入，以及 1440px 和 390px 导航。测试使用临时身份，不记录凭证截图或 trace。
- API 单元测试 61 项、模型测试 35 项、接口产物测试 20 项通过；前后端类型检查、前端 lint/格式/单元与组件测试/构建、文档检查通过。
- OpenAPI、权限目录已从可执行路由生成；Kysely 类型通过现有数据库实际 introspection 生成，与 schema 变更对应。

真实验证另外发现并修复：员工引用下拉框应提交 ID、员工重新启用错误地把保存快照当作输入，以及居间计算日期读回必须符合日期字符串契约。保留了对应回归。

## 环境收尾与限制

验证期间仅启动候选 API/Web 临时进程，结束后已关闭；测试数据已删除，原服务权限目录已恢复。原有两个用户、一个角色、零显式角色授权及 771 项权限保持；AUX、DCL、Approval、VOU、账簿和 WFL 实例均恢复为验证前的空业务状态。原 API `/readyz` 返回正常。

现有库已应用本片增量 schema（AUX 实体约束、三个引用列可空及 VOU 快照列）；没有部署新的应用镜像。浏览器验收仅声明本票两页，不代表其他尚未登记页面完成。
