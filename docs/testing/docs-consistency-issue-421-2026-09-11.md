# #421 文档归属与生成物检查验收

## 范围与结果

本票接续并核验 [2026-09-09 文档审计修订](docs-audit-2026-09-09.md)，补齐正式页面归属和检查闭环。当前 [覆盖报告](../use-cases/COVERAGE.md) 为 25 个 Registry 登记（含 VOU/RPT 参数家族）加 5 个带标题正式路由，共 30 个入口、22 份唯一用例；缺失和孤儿均为零。数量来自真实登记，不作为检查常量。本文不声称文档检查等于全业务验收。

十二个 APP/AUX 直接维护资源归入四个页面家族：用户与角色、基础分类、经营主体与员工、仓库/资金账户/车辆。资源特有场景从导航用例迁入所属家族，导航保留菜单与 Host 职责。`ResourceRegistration.useCaseKey` 为必填；缺失归属仍计入分母并失败，重复资源失败，共享有效用例通过。

ADR-0045/0046/0047 保持部分有效，分别在开头列明剩余条款与已被替代范围；ADR-0046 与 AUX 的 ADR-0053/0054 补齐双向部分替代。员工 current data、BOB 独立档案审批和 WFL 独立 runtime revision 按当前领域及 ADR-0058 解释，动态页面职责遵循 ADR-0060。没有恢复员工审批或 DCL 写入口。ADR 索引由原有生成器更新。

## 验证接缝

- 纯验证函数与 CLI：`pnpm docs:check`，14 项测试通过。覆盖缺归属、共享用例、资源重复、缺文档、模块领域副本、导入无仓库 I/O/输出，以及生成物真实 Git 状态与退出码。
- 文档生成与静态门禁：`pnpm docs:coverage`、`pnpm docs:adr-index` 对应原生 CLI、`make check-common check-ci-workflow` 通过；CI 工作流测试 16 项通过。空缺失基线、债务缩减比较及其专属测试和 CI 参数已移除。
- 类型检查：API、API client、model 与 frontend 的仓库 typecheck 入口通过。
- 前端：`pnpm --filter @zerp/frontend test:unit` 的 248 项普通单元测试及 23 项 Vuetify 测试通过；`build:target` 与 `lint` 通过。构建仍提示现有大 chunk，不影响成功退出。
- 本票没有业务规则、HTTP wire 或数据库结构变更；未重新运行全业务 API 集成及浏览器 E2E，也未部署。

## 隔离 CLI 验收

从当前候选创建仓库内隔离工作副本并建立独立 Git 基线；依赖复用本地安装。生成验证使用独立 Compose 项目 `zerp-issue421`、端口 `55521` 和可丢弃 `zerp_target_test` 数据库。Compose 配置有效且数据库健康。未使用共享业务服务或用户工作区运行漂移注入。

根级执行 `make generate-check`（覆盖 Compose 项目与端口），包级执行 `pnpm --filter @zerp/api generate:check`（注入同一可丢弃数据库）。每次均先实际生成业务契约及数据库类型，再执行同一 `scripts/check-generated.mjs`。包级不重建 Compose。

| 场景             | 注入方式                               | 根级退出码 | API 包级退出码 |
| ---------------- | -------------------------------------- | ---------- | -------------- |
| 无漂移           | 候选基线                               | 0          | 0              |
| 仅数据库类型漂移 | 提交被改变的数据库类型基线，生成后比较 | 2          | 1              |
| 仅业务契约漂移   | 提交被改变的 OpenAPI 基线，生成后比较  | 2          | 1              |
| 新增受管文件     | 生成目录新增未跟踪文件                 | 2          | 1              |
| 删除受管文件     | 删除已跟踪的额外生成文件               | 2          | 1              |

Make 用退出码 2 包装失败配方；两个入口的成功/失败结论一致。所有失败均确认到达统一差异检查，并非生成或连接数据库失败。持久回归测试额外覆盖暂存新增、两个受管路径的修改与删除，以及从根目录和 API 工作目录调用 CLI；非受管文件不导致误报。

隔离副本文档 CLI 的完整共享归属通过；省略用户归属、重复资源、删除家族文档、在 frontend 或 apps/api 下添加领域副本分别退出 1，恢复后退出 0。导入检查在禁止仓库读取/扫描和 Git 调用的子进程中验证，并确认不会因写参数生成文件或输出文本。

## 审查与资源回收

Standards 和 Spec 分别经独立只读审查，均无发现。既有文档修订保留并接续，本票没有更改业务实现。

验证完成后显式执行独立 Compose 项目的 `down --volumes --remove-orphans`，回读确认该项目没有容器、网络和卷。隔离副本及漂移注入工件随后删除；前端构建及测试进程均已退出，没有留下开发服务器或隧道。共享服务保持原状。
