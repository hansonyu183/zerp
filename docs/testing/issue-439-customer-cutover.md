# 客户与税务整体转换

权威规格：[ADR-0063](../adr/0063-customer-and-shared-tax-information.md)、[BOB](../domains/bob.md)、[AUX](../domains/aux.md)、[VOU](../domains/vou.md)、[ACC](../domains/acc.md)，对应 [#439](https://github.com/hansonyu183/zerp/issues/439)。

## 转换入口与边界

`apps/api/scripts/cutover-customers.ts` 是一次性的离线领域转换入口，输入是完成 DCL／BOB 归属分离后的数据库。运行时不读取旧客户结构；原始版本、权限、附件登记、收款与分录证据保存在 `dcl_customer_conversion_evidence`，只供审计和恢复追溯。

只读运行输出数据库基线、全部历史子单位到客户的映射、版本映射、收款拆分和审阅项：

```sh
node apps/api/scripts/cutover-customers.ts > .scratch/customer-baseline.json
```

连接从受控的 `TARGET_DATABASE_URL` 与 `TARGET_DATABASE_SCOPE` 读取。不得把连接串或真实备份写入版本库。

一生只有一个子单位时保留客户身份、编码和版本 ID；多个历史子单位全部获得新身份、编码及投影版本 ID。多单位客户的业务名称由原客户名称与该子单位名称组合，原文保留在转换证据。投影保留原版本号、审批状态、操作者和时间；历史已移除的客户仍可读取最后正式版本，但不能作为当前启用客户使用。根电话／地址与子单位业务电话／地址不同时阻断，不猜测覆盖。附件按文件身份合并，不丢弃根级或业务附件。

原税务必填资料缺失、同税号内容不同、身份／版本无法映射、无法判定归属的收款下游、未能转换的自定义执行规则均进入审阅清单。审阅项未解除不得应用。旧子单位维护权限删除，不转授其他权限。

跨子单位收款按原分摊形成独立客户收款。原来款、原分录和新单据的对应关系保留为证据；资金分录按原金额拆分，客户分录按原分户采用。逐源业务金额、客户账务、资金账户余额和空桶数量必须对平，每张投影凭证必须借贷平衡。反批准与重新批准通过目标领域服务执行。

## 应用与恢复

1. 完成 `make check`、`make test`、完整 `make target-e2e`，核对桌面与 390px 的客户、税务与发票实际菜单流程。记录候选提交 SHA。
2. 保留整套原应用，冻结写入并暂停后台任务。备份完整数据库及附件，记录原应用和目标应用的完整 SHA；实际备份文件的 SHA-256 必须与清单一致。
3. 在冻结状态重新执行只读检查并审阅映射。备份清单包含 `sourceReleaseSha`、`targetReleaseSha`、`database: {path, sha256}`、`attachments: {path, sha256}`。用现有启用的超级管理员身份标识转换操作者；新税务创建审计归属该操作者，历史审批证据保留原操作者。
4. 从对应目标发布工件运行应用命令，`ZERP_RELEASE_SHA` 必须等于清单中的目标 SHA：

```sh
node apps/api/scripts/cutover-customers.ts --apply \
  --baseline .scratch/customer-baseline.json \
  --backup .scratch/customer-backup-manifest.json \
  --actor-id "$MIGRATION_ACTOR_ID" --writers-frozen \
  > .scratch/customer-cutover-report.json
```

5. 入口先锁定全部源表并重验基线，再在同一事务建立目标结构、导入、转换引用、同步精确权限、核对金额和版本，最后原子切换。事务失败时源结构和数据一起回滚，不暴露部分转换；任何未通过的验证都不能以继续执行绕过。
6. 保持业务入口冻结，启动匹配 SHA 的整套目标 API／SPA，核对 `/healthz`、`/readyz`、发布身份及公开财务报表。全部通过后才恢复入口和后台写入。
7. 若转换后目标应用验收失败，继续冻结入口，停止目标应用，从同一份备份恢复数据库与附件，并恢复清单中的整套原应用；健康、原始基线及财务对账确认后才重新开放。不得将新应用搭配旧数据，也不得把旧应用接入已转换数据。

## 回归入口

- `customer-cutover.int.test.ts`：隔离 PostgreSQL 上的单／多／历史移除客户、开放版本、税务共享与冲突、缺失资料、属性冲突、引用缺失、附件登记、旧权限删除、晚期失败回滚；通过 Hono 读取投影档案和收款，并通过公开 RPT 查询核对迁移前后余额，验证收款反批准和再批准。
- `dcl-cutover.int.test.ts`：两片顺序执行后保留正式／历史读取与精确权限，分别验证失败恢复。
- `invoice-tax-http.int.test.ts`：税务 revision 并发、不可变发票内容、部分与跨期开票、未开票金额及来源反批准 blocker。

这些入口是验收范围说明，不代替实际命令退出码、发布 SHA、迁移报告和部署健康证据。
