# 会计映射管理

## 页面与依据

- 页面资源为 `acc/mapping`，由 [真实 Registry](../../../frontend/src/target/navigation/registry.ts) 装配。
- 业务规则见 [ACC 当前记账映射](../../domains/acc.md#7-当前记账映射)、[自动记账](../../domains/acc.md#8-vou-自动记账与删除) 和 [ADR-0056](../../adr/0056-acc-current-mapping.md)。
- 输入、响应与精确权限以 [可执行映射路由](../../../apps/api/src/app/contract.ts) 为准。

## `ACC-MAPPING-01` 当前配置查询

目录选项与查询分别检查精确权限。选择账簿后显式查询；翻页和写后刷新沿用已提交账簿。每行显示账簿、单据类型和中文默认结果，有详情权限才能打开。仅有保存权限时保留菜单，但不发送目录、列表或详情请求。

## `ACC-MAPPING-02` 直接维护

新建或打开后在临时表单编辑条件规则、凭证模板、固定或字段科目、借贷、金额币种、数量、辅助维度、成本对方科目及资产配置。已有配置身份不可编辑。保存失败保留输入；陈旧 revision 明确提示重新打开，不覆盖他人的修改。确认成功后刷新列表一次；刷新失败仍显示保存成功。未知写入禁止自动重试，通过有权的当前配置读取核实后再操作。

关闭、刷新、退出、账号切换或资源切换销毁临时输入。390px 下筛选与按钮换行，复杂编辑内容在对话框内滚动，页面不产生横向溢出。

## 验收场景

1. 从 Session 菜单进入映射页，选择账簿并保存；没有目录、读取或账簿权限时不泄露选项或当前内容。
2. 非法字段、冲突条件、模板或科目维度拒绝保存，当前配置、引用和审计不产生部分更新；两个相同 revision 保存仅一个成功。
3. 保存后批准 VOU 形成分录；修改配置再批准新单据，旧分录保持原采用 revision 与金额，新单据按新配置处理。下游失败时审批与全部记账事实回滚。
4. 旧主体与历史批准证据迁移后保持身份；未决候选返回 blocker，开放 V1 不被自动批准。旧 DCL 映射路由和生命周期权限不存在。
