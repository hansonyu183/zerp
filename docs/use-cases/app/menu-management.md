# 菜单管理用例

## 页面范围

- 路由：`/app/menu`
- 领域规则：[菜单模板](../../domains/app.md#39-菜单模板) 与 [菜单管理接口](../../domains/app.md#510-菜单管理)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [APP Schema](../../../contracts/openapi/schemas/app.yaml)
- 全站列表、筛选和行操作规范：[前端工程约束](../../../frontend/AGENTS.md)

菜单管理页面维护当前业务菜单，不授予权限。`DEFAULT` 由系统提供且只读；`BUSINESS` 保存后立即生效。

## `MNU-01` 加载与查看菜单

1. 页面读取当前模式、共享 `revision`、默认菜单、业务菜单、当前导航和可用路由；加载失败时显示错误与重试入口。
2. `DEFAULT` 只读；`BUSINESS` 可按领域规则编辑分组、顺序、显示名称、图标和启停。路由地址、路由键和权限代码只读。
3. 服务端读取时同步注册路由：新增路由自动追加到“其他/待归类”，已下线路由直接忽略并移除；页面使用响应中的最新 `revision` 和业务菜单。

## `MNU-02` 编辑并保存业务菜单

1. 仅拥有 `/app/menu/save-business` 时显示编辑与保存。拖拽、增删分组和路由、启停或修改展示信息后标记为脏。
2. 离开页面、切换模式、恢复模板或关闭有未保存修改的编辑区域前，必须确认是否放弃；不得静默保存。
3. 保存提交加载时取得的共享 `revision` 与完整业务菜单。成功后立即更新业务菜单；当前模式为 `BUSINESS` 时同时刷新当前管理员导航。
4. 并发冲突时保留当前编辑内容，提示刷新后重新决定，不自动合并。

## `MNU-03` 切换菜单模式

1. 仅拥有 `/app/menu/activate` 时显示模式切换。切换前必须二次确认。
2. 请求携带当前共享 `revision`，模式只允许 `DEFAULT` 或 `BUSINESS`。
3. 成功后刷新当前管理员自己的导航和版本；已打开页面不强制跳转。

## `MNU-04` 恢复业务归类模板

1. 仅拥有 `/app/menu/reset-business` 时显示恢复操作。恢复会替换当前业务菜单，必须二次确认；有本地未保存修改时先确认放弃。
2. 请求携带当前共享 `revision`。成功后模板立即生效；当前模式为 `BUSINESS` 时同时刷新当前管理员导航。

## 失败、并发与验收

- 保存、模式切换和恢复使用同一个 `revision`；冲突时不得自动重试、合并或降级。
- 其他用户在刷新页面、新开页面或恢复会话后读取最新菜单，无需退出重登。
- 验收覆盖：DEFAULT 只读；BUSINESS 保存即生效；新路由只追加到“其他/待归类”且不改变现有排序；已下线路由不可导航；无草稿、发布、目录版本或墓碑概念。
