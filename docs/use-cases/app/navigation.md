# 动态导航 Host 用例

## 范围

- 唯一业务资源路由为 `/:domain/:entity`，由 `app/navigation` 登记并由动态 Resource Host 承载。
- Navigation Resource 和 Navigation Entry 的来源、权限边界及未实现语义以 [APP 导航资源](../../domains/app.md#39-导航资源) 和 [ADR-0052](../../adr/0052-session-dynamic-navigation-and-page-migration.md) 为准。
- Registry 登记 `app/user` 的公共列表与用户编辑流程；其他未登记资源显示尚未实现。资源既有 API 及领域规则继续由各自领域文档拥有。

## `APP-NAVIGATION-01` 从会话装配入口

1. 登录或恢复成功后，页面从唯一 Session Context 的 `apiPaths` 取出非 Session 精确路径，按 `domain/entity` 去重并按领域分组。
2. 同一资源只显示一个 Navigation Entry；任一动作路径足以使入口可见，不能要求 `query` 或与页面 Registry 求交集。
3. 已知资源使用统一中文名称；未知遗留资源显示资源标识及待配置说明，不隐藏或猜测其业务能力。
4. Session 刷新得到新权限后，导航与直达资格同步重算；被撤销的资源入口和已挂载页面一并移除。

## `APP-NAVIGATION-02` 进入资源

1. 使用者从入口或直达 `/:domain/:entity` 进入时，Host 先用同一 Navigation Resource 判定资格。
2. 没有该资源时进入无权访问反馈，不挂载业务功能，也不发起业务请求。
3. 有资源且已登记时，Host 创建该资源的一次独立页面实例；页面自身只调用精确动作路径。
4. 有资源但未登记时，Host 显示明确的尚未实现反馈，不发送查询、不伪造空列表，也不回退旧页面。

## 验收

1. `session` 路径不产生导航入口；同资源多动作去重；仅有 `create` 的资源仍可进入但不查询。
2. 菜单、直达 URL 和权限变化使用同一资源资格；旧菜单树、菜单 API、`query` 过滤、前缀匹配和页面登记均不能改变入口资格。
3. `app/user` 进入真实公共列表与编辑器；其他未登记资源仍如实显示尚未实现。

## `APP-USER-01` 公共列表查询

领域规则引用 [APP 用户管理](../../domains/app.md#55-用户管理)，请求和响应以 [可执行用户路由](../../../apps/api/src/app/routes.ts) 和 [契约](../../../apps/api/src/app/contract.ts) 为准。

1. 从动态菜单进入用户资源时，Host 创建独立用户页面，公共 Shell 唯一持有列表、总数、页码、输入关键词、已提交查询、加载与查询错误状态。列表复用现有表格、分页、按钮与启停标签风格。
2. 拥有精确 query 权限才初始查询一次；仅有 create 时仍可进入，不查询，也不在创建成功后无权刷新。
3. 输入只改变待提交关键词；按钮或 Enter 提交，中文输入法选词不提交。新条件回第一页；翻页及写后刷新只采用已提交条件。
4. 查询响应必须属于当前页面和查询代次；乱序响应、写入前请求和已销毁页面的响应不能覆盖当前事实。

## `APP-USER-02` 新建与编辑

1. 新建依赖精确 create 与角色 query 权限；编辑依赖精确 get、save 与角色 query 权限。缺少依赖明确说明，不补授、不发送无权请求。角色选择复用现有分页角色查询，加载全部候选页并采用服务端 assignable。
2. 新建复用现有表单弹窗；每次编辑先读取新鲜详情，再填充名称和角色。身份字段只读，密码重置不进入此编辑器。
3. 保存失败保留表单；取消不写。编辑 Promise 只在保存确认成功或取消后结束。确认写成功才返回 changed 并触发一次公共刷新；void 不显示成功。
4. 同一行写入互斥，启停不乐观改值。并发冲突不更换版本自动重放。写成功而刷新失败时明确显示“写入成功、刷新失败”，不能诱导再次创建或启停。
5. 超时等未知结果先按已有读取权限核实；没有核实权限时明确结果未知，不自动重试。取消、关闭、退出、切换账号或卸载清除密码和临时编辑状态，不持久化草稿。

## 用户流程验收

- 使用超过一页的真实用户验证服务端编码、名称与拼音搜索、稳定分页以及 Session 与管理改名后的搜索变化。
- 真实创建、保存、启停及角色选择符合 APP 事务与授权规则；无权、上级目标、本人角色修改、系统身份和并发失败不留下部分写入。停用后所有旧会话失效，启用后不能复活。
- 可控异步测试验证输入法、查询乱序、同行重复写、成功后刷新失败、未知结果及销毁后的结果隔离；仅有 create 不触发 query。
- 桌面与 390px、明暗主题复用现有表格、弹窗和 AppSnackbar，主操作可用；不显示旧状态过滤、更新时间、只读详情或重置密码展示区。

## `APP-USER-03` 首片集成验收

1. 在同一可丢弃 PostgreSQL/API/Web 候选中，从真实登录、Session 恢复和动态菜单进入已登记用户页；缺少 `app/user` 登记必须使验收失败，不能以未实现提示替代。
2. 管理员通过公共列表新建用户并分配可分配角色；新用户在独立浏览器会话登录，完成必要改密、本人资料保存与刷新恢复。管理员以新的名称或拼音查询确认同一用户事实。
3. 管理员停用该用户后，其既有会话恢复失败；重新启用不能复活旧会话，新登录仍须使用当前密码。相关授权、事务与密码规则由 [APP](../../domains/app.md) 拥有。
4. 将真实链路与公开 VM、组件和 HTTP 集成证据对应到父规格的 M、D、L、U、S、C 验收组；仅登记用户页，不把其他资源未实现或全域归属冲突计为已完成。
5. 所有浏览器测试只连接隔离环境，敏感字段已填充时不采集截图、DOM 或调试日志；完成后回收本次启动的临时资源。
6. 本人资料弹窗在读取详情期间锁定输入和保存，保存期间锁定可变字段；迟到详情不能覆盖用户已开始编辑的内容。关闭或退出后不得重新填入旧资料。
