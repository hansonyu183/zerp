# 动态导航 Host 用例

## 范围

- 唯一业务资源路由为 `/:domain/:entity`，由 `app/navigation` 登记并由动态 Resource Host 承载。
- Navigation Resource 和 Navigation Entry 的来源、权限边界及未实现语义以 [APP 导航资源](../../domains/app.md#39-导航资源) 和 [ADR-0052](../../adr/0052-session-dynamic-navigation-and-page-migration.md) 为准。
- Registry 登记 `app/user`、`app/role`、`aux/employee-category`、`aux/position`、`aux/measurement-unit`、`aux/payment-method` 与 `aux/asset-category` 的公共列表与编辑流程；其他未登记资源显示尚未实现。资源既有 API 及领域规则继续由各自领域文档拥有。

## `APP-NAVIGATION-01` 从会话装配入口

1. 登录或恢复成功后，页面从唯一 Session Context 的 `apiPaths` 取出非 Session 精确路径，按 `domain/entity` 去重并按领域分组。
2. 同一资源只显示一个 Navigation Entry；任一动作路径足以使入口可见，不能要求 `query` 或与页面 Registry 求交集。
3. 已知资源使用统一中文名称；未知遗留资源显示资源标识及待配置说明，不隐藏或猜测其业务能力。
4. Session 刷新得到新权限后，导航与直达资格同步重算；被撤销的资源入口和已挂载页面一并移除。

## `APP-NAVIGATION-02` 进入资源

1. 使用者从入口或直达 `/:domain/:entity` 进入时，Host 先用同一 Navigation Resource 判定资格。
2. 没有该资源时进入无权访问反馈，不挂载业务功能，也不发起业务请求。
3. 有资源且已登记时，Host 创建该资源的一次独立页面实例；页面自身只调用精确动作路径。
4. 有资源但未登记时，Host 显示明确的尚未实现反馈，不发送查询、不伪造空列表，也不回退旧页面。

## 验收

1. `session` 路径不产生导航入口；同资源多动作去重；仅有 `create` 的资源仍可进入但不查询。
2. 菜单、直达 URL 和权限变化使用同一资源资格；旧菜单树、菜单 API、`query` 过滤、前缀匹配和页面登记均不能改变入口资格。
3. 已登记的用户、角色、人员类别、岗位、计量单位、收款方式与资产类别进入真实公共列表与编辑器；其他未登记资源仍如实显示尚未实现。

## `APP-USER-01` 公共列表查询

领域规则引用 [APP 用户管理](../../domains/app.md#55-用户管理)，请求和响应以 [可执行用户路由](../../../apps/api/src/app/routes.ts) 和 [契约](../../../apps/api/src/app/contract.ts) 为准。

1. 从动态菜单进入用户资源时，Host 创建独立用户页面，公共 Shell 唯一持有列表、总数、页码、输入关键词、已提交查询、加载与查询错误状态。列表复用现有表格、分页、按钮与启停标签风格。
2. 拥有精确 query 权限才初始查询一次；仅有 create 时仍可进入，不查询，也不在创建成功后无权刷新。
3. 输入只改变待提交关键词；按钮或 Enter 提交，中文输入法选词不提交。新条件回第一页；翻页及写后刷新只采用已提交条件。
4. 查询响应必须属于当前页面和查询代次；乱序响应、写入前请求和已销毁页面的响应不能覆盖当前事实。

## `APP-USER-02` 新建与编辑

1. 新建依赖精确 create 与角色 query 权限；编辑依赖精确 get、save 与角色 query 权限。缺少依赖明确说明，不补授、不发送无权请求。角色选择复用现有分页角色查询，加载全部候选页并采用服务端 assignable。
2. 新建复用现有表单弹窗；每次编辑先读取新鲜详情，再填充名称和角色。身份字段只读，密码重置不进入此编辑器。
3. 保存失败保留表单；取消不写。编辑 Promise 只在保存确认成功或取消后结束。确认写成功才返回 changed 并触发一次公共刷新；void 不显示成功。
4. 同一行写入互斥，启停不乐观改值。并发冲突不更换版本自动重放。写成功而刷新失败时明确显示“写入成功、刷新失败”，不能诱导再次创建或启停。
5. 超时等未知结果先按已有读取权限核实；没有核实权限时明确结果未知，不自动重试。取消、关闭、退出、切换账号或卸载清除密码和临时编辑状态，不持久化草稿。

## 用户流程验收

- 使用超过一页的真实用户验证服务端编码、名称与拼音搜索、稳定分页以及 Session 与管理改名后的搜索变化。
- 真实创建、保存、启停及角色选择符合 APP 事务与授权规则；无权、上级目标、本人角色修改、系统身份和并发失败不留下部分写入。停用后所有旧会话失效，启用后不能复活。
- 可控异步测试验证输入法、查询乱序、同行重复写、成功后刷新失败、未知结果及销毁后的结果隔离；仅有 create 不触发 query。
- 桌面与 390px、明暗主题复用现有表格、弹窗和 AppSnackbar，主操作可用；不显示旧 status 协议过滤、更新时间、只读详情或重置密码展示区。

## `APP-USER-03` 首片集成验收

1. 在同一可丢弃 PostgreSQL/API/Web 候选中，从真实登录、Session 恢复和动态菜单进入已登记用户页；缺少 `app/user` 登记必须使验收失败，不能以未实现提示替代。
2. 管理员通过公共列表新建用户并分配可分配角色；新用户在独立浏览器会话登录，完成必要改密、本人资料保存与刷新恢复。管理员以新的名称或拼音查询确认同一用户事实。
3. 管理员停用该用户后，其既有会话恢复失败；重新启用不能复活旧会话，新登录仍须使用当前密码。相关授权、事务与密码规则由 [APP](../../domains/app.md) 拥有。
4. 将真实链路与公开 VM、组件和 HTTP 集成证据对应到父规格的 M、D、L、U、S、C 验收组；仅登记用户页，不把其他资源未实现或全域归属冲突计为已完成。
5. 所有浏览器测试只连接隔离环境，敏感字段已填充时不采集截图、DOM 或调试日志；完成后回收本次启动的临时资源。
6. 本人资料弹窗在读取详情期间锁定输入和保存，保存期间锁定可变字段；迟到详情不能覆盖用户已开始编辑的内容。关闭或退出后不得重新填入旧资料。

## 角色管理（#385）

角色资源通过 Registry、ResourceHost、公共 ListPageShell 与角色 VM 接入，业务规则引用 [APP 角色管理](../../domains/app.md#56-角色管理)，请求以 `apps/api/src/app/independent-contract.ts` 的可执行角色及权限路由为准。

1. 按关键词显式搜索编码、拼音或名称，固定每页 20 条，默认保留停用角色；桌面和 390px 使用同一 Shell。
2. 新建仅填写名称、说明和权限；编辑先读取新鲜详情。权限目录按精确 query 权限逐页读取，路径分组仅用于显示，不自动选择 query/get。缺少详情、保存或目录读取依赖时不启动编辑、不发无权请求。
3. 已关联停用权限持续显示并标记停用，必须明确移除后保存；不静默改写权限集合。内置角色和自持角色按服务端资格限制操作。
4. 写入成功才返回 changed，由公共 VM 刷新一次；取消不刷新，写后刷新失败仍提示写入成功。未知结果不重放、不因状态相同而推断本次成功；卸载、换用户或授权变化隔离旧响应。
5. 用户编辑器逐页获取角色候选并合并详情关联；停用或不可分配角色仍可见，提交集合遵循 APP 用户管理规则。
6. 闭环验收：创建只授予某资源单项非 query 权限的角色，分配用户，恢复 Session 后资源菜单可见且没有越权查询；停用角色后下一受保护请求拒绝已撤权限，恢复后菜单与页面实例撤销，角色关联与用户会话保留。

## 人员类别与岗位管理（#386）

两页由 Registry 分别登记 `aux/employee-category` 与 `aux/position`，均沿动态 Host、公共 ListPageShell 和模块 VM 调用类型化 API。规则引用 [AUX 管理查询与并发](../../domains/aux.md#21-管理查询与并发)及[人员类别、部门与岗位](../../domains/aux.md#32-人员类别部门与岗位)，接口以 [AUX 可执行契约](../../../apps/api/src/app/aux-contract.ts)及其路由为准。

1. 页面只在拥有精确 query 权限时初始加载一次；输入关键词后显式搜索，翻页与写后刷新使用已提交条件。仅有其他动作权限仍可进入页面，不补发无权查询。
2. 新建与编辑共用名称、说明展示表单，各实体静态绑定自己的类型化 API；编辑依赖 get 与 save，读取新鲜详情再填充表单。缺少真实依赖时说明原因，不启动无权流程。
3. 以服务端动作资格和精确动作授权共同控制编辑、启用、停用；操作期间同行互斥。创建或保存成功才返回 changed，取消不刷新，写成功但刷新失败仍报告写入成功。
4. 结果未知时保留输入并提示核实，不自动重放、不更换 revision 重试；创建成功而详情读回失败时保留已创建 ID，不能再次创建。卸载、换用户或权限变化后忽略旧响应。
5. 两页分别在桌面与 390px 验证超过一页数据的中文、拼音、编码搜索、分页、新建、改名和启停；通过可控异步覆盖失败、取消、重复点击和迟到响应。历史引用采用与删除 blocker 由领域服务测试验证，页面不新增删除按钮。
6. 十二个 AUX 管理契约统一并不代表十二页交付；后续页面按下列分片登记，未登记的 AUX 资源仍显示尚未实现。

## 计量单位管理（#387）

`aux/measurement-unit` 由 Registry 登记，独立的 `measurement-unit/vm.ts` 和编辑器通过公共列表进入类型化 API。编辑器只提供名称、符号、数量精度；规则引用 [AUX 计量单位](../../domains/aux.md#35-计量单位)，协议以 [AUX 可执行契约](../../../apps/api/src/app/aux-contract.ts) 为准。新建与编辑显式构造所属输入，编辑保留详情字符串 revision；取消无刷新，确认写成功后刷新失败仍报告成功，未知结果与冲突禁止自动重放。验收覆盖桌面和 390px 的菜单、超过一页的数据检索、创建、编辑与启停。

## 收款方式管理（#388）

`aux/payment-method` 通过动态 Host、公共 ListPageShell、同目录 VM 和专有编辑器进入类型化 API。金额、启停和历史采用规则引用 [AUX 收款方式](../../domains/aux.md#34-收款方式)与[字段采用分类](../../domains/aux.md#41-字段采用分类)，请求和响应以 [AUX 可执行契约](../../../apps/api/src/app/aux-contract.ts)及[路由登记](../../../apps/api/src/app/independent-contract.ts)为准。

1. 拥有精确 query 权限才加载列表；名称、编码、拼音按已提交查询搜索及分页。编辑需要 get/save，读取新鲜详情再填入名称、默认销售加价和说明；界面金额输入始终作为字符串传递。
2. 取消不刷新；非法输入或保存失败保留编辑内容。确认写成功才返回 changed；刷新失败仍说明写入成功，并保留已创建 ID。
3. 陈旧 revision 显示冲突并停止再次提交；未知结果提示核实，不自动重放。卸载或会话变化隔离迟到响应。
4. 桌面和 390px 从菜单完成超过一页数据的检索、新建、编辑和启停；验证金额回填、取消、保存失败、并发冲突及写后刷新失败。历史采用事实由所属领域公开接口验证，页面登记不代表历史消费者验收完成。

## 资产类别管理（#389）

`aux/asset-category` 通过动态 Host、公共 ListPageShell、同目录 VM 和专有编辑器进入类型化 API。字段约束和采用规则引用 [AUX 资产类别](../../domains/aux.md#38-资产类别)与[字段采用分类](../../domains/aux.md#41-字段采用分类)，请求和响应以 [AUX 可执行契约](../../../apps/api/src/app/aux-contract.ts)及[路由登记](../../../apps/api/src/app/independent-contract.ts)为准。

1. 页面按名称、编码或拼音显式搜索，固定每页 20 条。编辑需要精确 get/save 权限并先读取新鲜详情；编码由服务端分配且不进入表单。
2. 表单显式编辑名称、1–1200 整数自然月、0.00–99.99 且最多两位小数的残值率和说明。期限以整数传递，残值率全程保持十进制字符串。
3. 取消不刷新；非法输入和已知保存失败保留编辑内容。确认写成功才返回 changed；写后刷新失败仍报告成功，冲突或未知结果禁止自动重放。
4. 新建类别立即启用，停用类别不再出现在 VOU 新购置候选中；候选同时携带当前期限和残值率供新行采用。购置单保存后持有自己的类别名称、期限和残值率快照，类别后续修改或停用不回写、不重算。
5. 桌面和 390px 从菜单完成超过一页数据的检索、新建、编辑与启停，并覆盖合法端点、非法精度、取消、冲突和写成功后刷新失败。

## 第二批验收状态（#390）

七页及 Session/导航已通过真实 PostgreSQL/API/Web 的桌面和 390px 浏览器验证，包括角色单项授权、用户分配、Session 恢复入口和停用回收闭环。逐项证据见 [#390 集成验收记录](../../testing/second-batch-integration-issue-390-2026-09-07.md)。计量单位与收款方式的 AUX 页面和产品/客户历史采用已验证；VOU 交易单位精度/完整审计快照，以及销售订单收款方式/加价快照已在独立切片补齐并验证。第二批整体验收结果以该记录为准，不宣称全域页面迁移完成。

## 七页动态字段验收（#393）

1. 用户、角色、员工分类、岗位、计量单位、收款方式、资产类别均从真实菜单经同一 Registry/Host 登记进入；完整必需列与扩展列交给同一渲染器，专有编辑器保持可用。
2. 扩展已有字段的展示和合法筛选时，只改页面登记与该资源明确查询绑定；Shell 不识别资源名或字段业务名称。筛选在服务端完整授权集合中执行，后计数分页，多个条件 AND，文本中的 SQL 通配字符按字面匹配。
3. 提交筛选后修改尚未提交输入，翻页及写后刷新仍使用完整深复制快照；范围端点、0、false 不丢失。无权查询或引用不请求，仅有非 query 权限仍可进入。
4. 取消不刷新，changed 只刷新一次；查询成功不能解锁未知写入。已确认写成功但刷新失败单独反馈，不能自动重放写入。
5. 七页在桌面和 390px 可查询、分页及打开专有编辑器；非法字段、缺必需字段、未知枚举、重复身份明确报错，不使用空白或替代身份掩盖。
