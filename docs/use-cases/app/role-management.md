# 角色管理用例

## 页面范围

- 路由：`/app/role`
- 领域规则：[APP 角色与授权规则](../../domains/app.md)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [APP Schema](../../../contracts/openapi/schemas/app.yaml)
- 全站筛选和行操作规范：[前端工程约束](../../../frontend/AGENTS.md)

## 查询与只读详情

页面入口要求角色查询权限，首次加载固定查询第 1 页。关键词草稿只在回车或查询时提交，状态草稿只在应用筛选时提交；应用和重置回到第 1 页。并发请求只接收最后一次结果，失败时保留已应用条件、现有列表和可见重试入口。

列表直接使用服务端返回的动作集合装配全部桌面和手机行操作。查看只请求角色详情并展示完整权限和审计资料；没有保存权限或目标不可维护时仍保持只读，不把协议动作、状态或角色类型直接作为文案。

## 创建与编辑

创建入口同时要求角色创建和权限目录查询能力。页面只收集名称、可选说明和至少一个权限，不显示或提交角色编码。权限目录加载失败时保留可恢复错误并禁止保存；成功后关闭表单、清空输入并重新查询列表。

编辑入口必须同时满足服务端 `EDIT` 动作以及查看、保存、权限目录查询能力。页面使用最近一次详情的 revision，保留后来停用的既有权限并要求显式移除。冲突时保留全部输入并要求重新加载，不自动合并、重试或覆盖。

创建或编辑表单变脏后，关闭按钮、遮罩、Escape 和路由离开都进入同一放弃确认。成功编辑后重新读取当前会话、菜单、角色详情和列表，使最新授权事实立即生效。

## 启用与停用

行上只呈现服务端返回的 `ENABLE` 或 `DISABLE`。停用确认说明关联用户从下一次请求开始立即失去该角色权限贡献；启用确认说明当前仍启用的权限会重新贡献。提交期间只锁定目标行且不乐观改写；成功后重新查询，冲突则刷新事实并要求重新发起决定。

## 验收场景

- `system`、`superadmin` 与普通角色同时可见，特殊角色只有安全的只读动作；
- 状态、角色类型和动作使用共享中文映射，选择项从同一映射派生；
- 自动编码、唯一名称、授权上限、原子回滚和并发 revision 由真实后端验证；
- 脏表单的所有离开方式得到同一确认；
- 手机布局保留服务端允许的全部行操作；
- 角色停用和重新启用不撤销会话，并从下一次受保护请求起改变有效权限。
