# 登录页用例

## 页面范围

- 路由：`/signin`
- 领域规则：[APP 访问、会话与权限领域](../../domains/app.md)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [APP Schema](../../../contracts/openapi/schemas/app.yaml)

## `LGN-01` 用户名密码登录

### 触发与前端处理

1. 用户输入用户名和密码；前端去除用户名首尾空白，保持密码原值。
2. 任一字段为空时禁止提交，提交期间禁止重复提交。
3. 前端调用 `POST /app/user/signin`。
4. 成功后保存用户资料、CSRF Token 和展开后的权限集合，再读取当前用户菜单。
5. `redirect` 只有以单个 `/` 开头时才是合法站内地址；拒绝 `//` 和外部 URL。存在合法地址时进入原目标，否则进入 `/home/dashboard`。
6. 无论成功或失败都清空密码并保留用户名。中文业务原因直接展示；网络、超时、协议和内部错误使用脱敏提示。

### 后端协作与结果

登录限流、固定成本认证、账号状态、失败锁定、权限装配、审计、会话与 Cookie 规则统一由 APP 领域的登录动作负责，页面不复制或推断这些规则。

登录成功以服务端会话建立为准，不以菜单读取成功为前提。会话已建立而菜单读取发生非认证错误时，前端保留会话并进入目标页面，同时显示明确的“菜单加载失败”提示和重新加载入口；菜单读取表明会话失效时，前端清除本地会话并返回登录页。

## `LGN-02` 未登录访问受保护页面

### 前端处理

1. 首次进入受保护页面时，路由守卫先调用 `POST /app/user/session` 恢复 Cookie 会话，不能先闪现登录页。
2. 会话无效时才进入登录页，并在 `redirect` 中保留原站内完整路径、查询参数和锚点。
3. 登录成功后重新进入原目标地址，使用最新权限和最新菜单重新注册、匹配并鉴权路由。
4. 用户能够登录但没有目标页面权限时进入“无权访问”；目标路由不存在时进入“页面不存在”；没有合法原目标时才进入工作台。

### 后端协作与结果

后端不接收也不信任页面 `redirect`。会话恢复、CSRF 轮换和期限规则由 APP 领域的会话动作负责；登录后的每个业务请求仍独立校验会话、CSRF、精确接口权限、数据范围和业务状态。

## `LGN-03` 已登录用户访问登录页

1. 前端已经初始化且确认会话有效时，访问 `/signin` 不显示登录表单、不再次提交凭证，也不创建第二个会话，一律进入 `/home/dashboard`。
2. `/signin` 上人为附加的 `redirect` 不改变该规则；正常深链由 `LGN-02` 在原目标路由恢复。
3. 应用尚未初始化时先恢复会话；成功后进入工作台，失败时清除本地会话和失效 Cookie，再显示登录页。
4. 会话恢复不产生新的登录成功审计，也不创建新会话。

## 验收场景

- 登录成功和失败后密码均清空、用户名保留，重复提交受控；
- `redirect` 保留查询参数与锚点，并拒绝 `//` 和外部跳转；
- 菜单非认证失败时会话仍有效、进入目标页且存在可见重试入口；菜单认证失败时清除会话并回登录页；
- 未登录深链在登录后返回原地址；无权时进入“无权访问”，不存在时进入“页面不存在”；
- 有效会话访问带或不带 `redirect` 的 `/signin` 均进入工作台，且不再次登录。
