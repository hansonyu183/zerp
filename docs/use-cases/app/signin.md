# 登录页用例

## 页面范围

- 路由：`/signin`、`/change-password`
- 领域规则：[登录](../../domains/app.md#51-登录)、[当前用户自助接口](../../domains/app.md#54-当前用户自助接口) 与 [最终权限计算](../../domains/app.md#4-最终权限计算)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [APP Schema](../../../contracts/openapi/schemas/app.yaml)

## `LGN-01` 用户名密码登录

### 触发与前端处理

1. 用户输入用户名和密码；前端去除用户名首尾空白，保持密码原值。
2. 任一字段为空时禁止提交，提交期间禁止重复提交。
3. 前端调用 `POST /app/user/signin`。
4. 成功后保存用户资料、CSRF Token 和展开后的权限集合，再读取当前用户菜单。
5. `redirect` 只有以单个 `/` 开头时才是合法站内地址；拒绝 `//` 和外部 URL。存在合法地址时进入原目标，否则进入 `/home/dashboard`。
6. 无论成功或失败都清空密码并保留用户名。中文业务原因直接展示；网络、超时、协议和内部错误使用脱敏提示。

### 后端协作与结果

固定成本认证、账号状态、失败计数与锁定、权限装配、审计、会话与 Cookie 规则统一由 APP 领域的登录动作负责，页面不复制或推断这些规则。当前系统不提供进程内登录限流；若以后需要限流，必须采用独立且可部署一致的设计。

登录成功以服务端会话建立为准，不以菜单读取成功为前提。会话已建立而菜单读取发生非认证错误时，前端保留会话并进入目标页面，同时显示明确的“菜单加载失败”提示和重新加载入口；菜单读取表明会话失效时，前端清除本地会话并返回登录页。

## `LGN-02` 未登录访问受保护页面

### 前端处理

1. 首次进入受保护页面时，路由守卫先调用 `POST /app/user/session` 恢复 Cookie 会话，不能先闪现登录页。
2. 会话无效时才进入登录页，并在 `redirect` 中保留原站内完整路径、查询参数和锚点。
3. 登录成功后重新进入原目标地址，使用最新权限和最新菜单重新注册、匹配并鉴权路由。
4. 用户能够登录但没有目标页面权限时进入“无权访问”；目标路由不存在时进入“页面不存在”；没有合法原目标时才进入工作台。

### 后端协作与结果

后端不接收也不信任页面 `redirect`。会话恢复、同一会话固定 CSRF Token 的重新签发和期限规则由 APP 领域的会话动作负责；多个标签页恢复同一 Cookie 会话时不得互相使 Token 失效。登录后的每个业务请求仍独立校验会话、CSRF、精确接口权限、数据范围和业务状态。

## `LGN-03` 已登录用户访问登录页

1. 前端已经初始化且确认会话有效时，访问 `/signin` 不显示登录表单、不再次提交凭证，也不创建第二个会话，一律进入 `/home/dashboard`。
2. `/signin` 上人为附加的 `redirect` 不改变该规则；正常深链由 `LGN-02` 在原目标路由恢复。
3. 应用尚未初始化时先恢复会话；成功后进入工作台，失败时清除本地会话和失效 Cookie，再显示登录页。
4. 会话恢复不产生新的登录成功审计，也不创建新会话。

## `LGN-04` 首次登录强制修改初始密码

1. 登录响应标明当前会话必须先修改密码时，页面进入强制改密流程；受限会话规则以[最终权限计算](../../domains/app.md#4-最终权限计算)为准。
2. 前端丢弃登录前保存的业务 `redirect`，不读取普通菜单，直接进入独立路由 `/change-password`。该页不使用 `AppLayout`，不显示业务导航，只提供修改本人密码和安全退出。
3. 页面刷新、重新打开或直接输入其他地址时，前端先恢复会话；只要强制改密标记仍存在，就返回 `/change-password`，不因已有权限数组放行普通页面。
4. 用户提交当前初始密码和符合策略的新密码。修改成功后，前端清除本地会话并进入 `/signin`，提示使用新密码重新登录；服务端状态变化以[当前用户自助接口](../../domains/app.md#54-当前用户自助接口)为准。
5. 用户使用新密码重新登录后直接进入 `/home/dashboard`，不得恢复强制改密前丢弃的业务 `redirect`。
6. 修改失败时保留受限会话和改密界面，清空密码输入并显示脱敏后的具体业务原因。

## 验收场景

- 登录成功和失败后密码均清空、用户名保留，重复提交受控；
- `redirect` 保留查询参数与锚点，并拒绝 `//` 和外部跳转；
- 菜单非认证失败时会话仍有效、进入目标页且存在可见重试入口；菜单认证失败时清除会话并回登录页；
- 未登录深链在登录后返回原地址；无权时进入“无权访问”，不存在时进入“页面不存在”；
- 有效会话访问带或不带 `redirect` 的 `/signin` 均进入工作台，且不再次登录。
- 同一 Cookie 会话在多个标签页分别恢复后，各标签页继续提交的 CSRF Token 均有效；重复恢复返回同一个 Token。
- 初始密码登录后只能进入强制改密流程，直接访问业务路由也被前后端拒绝；
- 强制改密页不显示 `AppLayout` 或业务菜单，刷新和直接访问其他地址仍回到该页；
- 改密成功后返回登录页，原业务 `redirect` 被丢弃，使用新密码重新登录后进入工作台。
