# 系统参数管理用例

## 页面范围

- 路由：`/app/system-parameter`
- 领域规则：[系统参数模型](../../domains/app.md#38-系统参数)、[系统参数接口](../../domains/app.md#59-系统参数) 与 [管理接口通用规则](../../domains/app.md#6-管理接口通用规则)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [APP Schema](../../../contracts/openapi/schemas/app.yaml)
- 全站列表、筛选和并发请求规范：[前端工程约束](../../../frontend/AGENTS.md)

页面只管理已注册的非敏感参数值。它不能创建、删除或修改参数键、名称、说明、类型、默认值、约束或生效模式；密码、密钥、Token、Cookie、数据库连接和其他凭证不在本页出现。`app.menu.mode` 可查询但由菜单服务维护，始终只读。

## `SPM-01` 查询系统参数

### 前端处理

1. 页面入口要求当前用户拥有 `/app/system-parameter/query`；没有该权限时由路由守卫进入“无权访问”。
2. 查询条件采用全站明确提交筛选：关键词、值类型和可编辑状态只在用户明确提交查询或应用筛选后生效；应用或重置筛选回到第 1 页。列表固定每页 20 条，按参数键升序。
3. 列表直接展示所有已注册非敏感参数的键、名称、说明、值类型、配置值、默认值、可编辑状态和生效模式；不要求先打开详情才能读取值。`RESTART_REQUIRED` 还展示运行值与 `restartPending`，以明确区分配置值和运行值。
4. 用户可见的生效模式选择和标签从同一中文映射派生：`IMMEDIATE` 为“立即生效”、`NEXT_REQUEST` 为“下次请求生效”、`RESTART_REQUIRED` 为“重启后生效”；已知值不得显示协议原码。
5. 只有同时拥有 `/app/system-parameter/get` 时列表才提供查看入口；只有同时拥有 `get` 和相应写权限时才显示编辑或恢复默认入口。`editable=false`、没有充分注册约束的参数和 `app.menu.mode` 均不显示编辑或恢复默认入口。

### 后端协作与结果

`query` 独立校验有效会话、CSRF 和 `/app/system-parameter/query` 精确权限，只接受 OpenAPI 白名单中的筛选、分页和排序。结果直接返回已注册非敏感参数的配置值和默认值；`get` 不作为列表值读取的额外安全边界。后端仍不得因为列表可见而跳过后续 `get`、`save` 或 `reset` 的独立权限与业务校验。

## `SPM-02` 查看与编辑系统参数

### 前端处理

1. 查看详情要求 `/app/system-parameter/get`。每次进入编辑前必须调用 `POST /app/system-parameter/get` 读取最新完整详情、可编辑状态和 `revision`；列表行不能替代这次新鲜读取。没有 `save` 权限、参数不可编辑、没有充分注册约束或参数为 `app.menu.mode` 时详情保持只读。
2. 编辑控件、候选值、必填提示和校验提示必须由同一份参数约束元数据派生；不得猜测约束或用通用自由文本绕过约束。默认值、当前配置值和拟保存值都必须满足基础类型及参数专属约束。前端校验只改善反馈，后端校验不可省略。
3. 可编辑详情展示配置值、默认值、生效模式和审计信息。对 `RESTART_REQUIRED` 另展示运行值及是否待重启；页面不提供重启入口，也不宣称保存已改变运行值。
4. 表单有未保存修改时关闭抽屉或离开详情必须确认是否放弃。保存提交编辑前 `get` 返回的 `revision`；提交期间禁止重复保存。成功后关闭或刷新详情，并重新查询列表，不在前端猜测写后状态。
5. `revision` 冲突时保留用户输入，提示数据已经变化并要求重新加载后再决定；不自动合并、重试或覆盖。详情连续切换参数时只接受当前选中参数的最新响应。

### 后端协作与结果

`get` 独立校验有效会话、CSRF 和 `/app/system-parameter/get` 精确权限，并返回已注册的最新完整非敏感参数详情、`revision` 和可编辑状态。`save` 独立校验 `/app/system-parameter/save`、参数已注册且允许通用编辑、当前 `revision`、基础类型和注册约束；不因调用过 `get` 而省略任何校验。

保存成功只更新配置值和 `revision`，并按领域规则处理生效模式：`IMMEDIATE` 明确为立即生效，`NEXT_REQUEST` 明确为下次请求生效，二者均不产生待重启状态；`RESTART_REQUIRED` 保持运行值，并对每个新版本设置或保留 `restartPending`，即使配置文本改回旧运行值也不能跳过最新版本采用证明。重启后的每个服务实例从固定部署配置取得自己的身份和完整实例清单，实际加载配置版本后只为自身上报；全部实例自报完成前保持待重启，且不存在页面、通用参数接口或人工命令代报其他实例的入口。审计记录操作而不记录修改前后的参数值。

## `SPM-03` 恢复默认值

### 前端处理

1. 恢复默认值要求同时拥有 `/app/system-parameter/get` 和 `/app/system-parameter/reset`。操作前先读取最新详情；`editable=false`、没有充分注册约束和 `app.menu.mode` 不提供入口。
2. 二次确认明确展示参数名称、将恢复的默认值与生效模式；确认后提交最新详情的 `revision`，提交期间禁止重复操作。
3. 成功后重新读取或刷新详情与列表。`IMMEDIATE` 和 `NEXT_REQUEST` 按其明确生效语义显示成功且不标记待重启；`RESTART_REQUIRED` 仅确认配置值已恢复，继续展示旧运行值与 `restartPending`（如仍未完成运行实例证明），不提供或触发重启。
4. `revision` 冲突时保留当前详情和操作上下文，提示重新加载后再次确认；不自动重试。用户取消确认不发送请求。

### 后端协作与结果

`reset` 独立校验有效会话、CSRF、`/app/system-parameter/reset` 精确权限、参数已注册且允许通用编辑、当前 `revision`，并验证注册默认值满足基础类型及参数专属约束。成功时将配置值恢复为默认值、增加 `revision` 并记录不含参数值的审计；生效模式、运行值和待重启的处理与 `save` 完全一致。

## 失败与并发响应

- 列表、详情或筛选请求失败时保留当前筛选、分页和选中参数，显示脱敏业务错误与重试入口；不得伪装成空列表、空详情或使用假数据。
- 并发列表查询只接受最后一次请求响应；较早响应不得覆盖较新的筛选、分页或列表。详情与编辑前读取同样只接受当前选中参数的最新响应。
- `get` 后参数可能被注册流程、菜单服务或其他管理员改变；`save` 和 `reset` 必须以 `revision` 拒绝陈旧写入。冲突不自动合并、重试或把旧输入写回。
- 没有权限、参数未注册、参数只读、约束缺失或校验失败时，后端返回稳定且不泄露内部实现的业务错误。前端不得依赖隐藏按钮作为授权或校验。
- `RESTART_REQUIRED` 的实例采用证明不完整、失败或延迟时，页面保留已知运行值与 `restartPending`，不得推测已完成重启或把配置值显示为运行值。

## 验收场景

- 没有 `query` 权限无法进入页面；没有 `get`、`save` 或 `reset` 时分别没有相应入口，伪造请求仍由后端拒绝。
- 筛选只在明确提交后生效，每页固定 20 条，参数键升序；列表直接显示所有已注册非敏感参数的配置值和默认值。
- 编辑前必经最新 `get`；控件和提示由约束元数据派生。未注册充分约束、不可编辑参数及 `app.menu.mode` 全程只读。
- 页面不能创建、删除或变更参数元数据，且不显示或登记敏感凭证类参数。
- `save` 与 `reset` 均校验 `revision`、基础类型和注册约束；默认值、既有配置值与新值不符合约束时不会被静默转换或重置。
- 三种生效模式使用中文映射，已知值不显示协议原码；`IMMEDIATE`、`NEXT_REQUEST` 不产生待重启，`RESTART_REQUIRED` 只更新配置值并在运行实例证明完整前保留旧运行值与待重启。
- 关闭已修改表单必须确认放弃；恢复默认值必须二次确认；冲突与其他失败不覆盖输入或伪装成功。
