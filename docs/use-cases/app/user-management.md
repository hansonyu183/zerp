# 用户管理用例

## 页面范围

- 路由：`/app/user`
- 领域规则：[用户](../../domains/app.md#33-用户)、[用户管理](../../domains/app.md#56-用户管理)、[当前用户自助接口](../../domains/app.md#54-当前用户自助接口) 与 [事务一致性](../../domains/app.md#7-事务与一致性)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [APP Schema](../../../contracts/openapi/schemas/app.yaml)
- 全站筛选和行操作规范：[前端工程约束](../../../frontend/AGENTS.md)

## `USR-01` 查询用户列表

### 前端处理

1. 页面入口要求当前用户拥有 `/app/user/query`；没有该权限时由路由守卫进入“无权访问”。
2. 首次进入查询第 1 页，每页固定 20 条，默认按用户名升序排列。
3. 关键词匹配用户名或显示名称；状态筛选只提供“启用”和“停用”。输入关键词后按回车或点击“查询”才发起请求，状态变化后点击“应用筛选”才发起请求。
4. 应用或重置筛选都回到第 1 页。查询失败时保留当前条件并显示错误和重试入口。
5. 并发查询只接受最后一次请求的响应，较早响应不得覆盖较新的查询条件和结果。
6. 系统内置用户在列表中显示为只读用户，不提供编辑、启用或停用操作。
7. 筛选区域的响应式默认状态和行操作数量分流统一遵循前端工程约束，页面不自行实现例外。

### 后端协作与结果

查询资格、返回范围和系统身份规则以[用户管理](../../domains/app.md#56-用户管理)为准；页面仅展示 OpenAPI 查询投影。

## `USR-02` 新建用户

### 前端处理

1. “新增”入口要求当前用户同时拥有 `/app/user/create` 和 `/app/role/query`。
2. 打开新增抽屉后加载角色目录，只把后端标记为可分配的启用角色作为候选；系统角色不显示，停用角色不能新选。角色加载失败时保留错误并禁止保存。
3. 管理员填写用户名、显示名称、初始密码，并至少选择一个启用角色。用户名去除首尾空白，密码保持原值且不回显。
4. 用户名创建后不可修改；密码策略和角色授权安全性由后端最终校验。
5. 表单已经修改时关闭抽屉必须确认是否放弃；确认放弃或创建成功后立即清空密码和全部表单状态。
6. 创建成功后关闭抽屉并重新查询当前列表。页面不得显示、复制或再次返回初始密码。

### 后端协作与结果

创建资格、初始状态、授权与事务规则以[用户管理](../../domains/app.md#56-用户管理)为准；页面只处理成功或失败的可观察结果。

新用户第一次使用初始密码登录后，在完成本人密码修改前不能进入或调用普通业务功能；具体登录编排见[登录页 `LGN-04`](signin.md)。

## `USR-03` 查看与编辑用户

### 前端处理

1. 当前用户拥有 `/app/user/get` 时，列表提供用户详情入口；同时拥有 `/app/user/save` 和 `/app/role/query` 时显示“编辑”，否则显示“查看”。根据通用操作规范，同时满足查看和编辑条件时只显示“编辑”。
2. 查看模式只调用 `POST /app/user/get` 并以只读方式展示用户名、显示名称、状态、角色和审计信息。编辑模式打开抽屉后同时读取用户最新详情和角色目录；任一请求失败时保留错误与重试入口，并禁止保存。候选只包含服务端标记为可分配的启用角色，既有但不可分配的关联仍在详情中显示。
3. 用户名和状态始终只读；普通编辑只允许修改显示名称和完整角色集合。目标是当前登录用户本人或后端判定目标不可维护时，角色选择器只读；不可维护目标整体保持只读，本人仍只允许修改显示名称。
4. 已分配但后来停用的角色仍显示在详情中并标记“已停用”，不能作为有效选择保留。编辑其他用户时必须由管理员明确移除全部停用角色后才能保存，前端不得自动删除或隐藏这些关联。
5. 表单已修改时关闭抽屉必须确认是否放弃。保存时提交加载详情所得的 `revision`；保存成功后关闭抽屉并重新查询当前列表。
6. 数据冲突时保留抽屉和用户输入，提示详情已变化并要求用户重新加载后再决定，不自动合并或重试写入。

### 后端协作与结果

详情、目标可维护性、角色集合和事务规则以[用户管理](../../domains/app.md#56-用户管理)为准。页面不因已经读取详情或角色目录而推断写入一定成功。

## `USR-04` 启用与停用用户

### 前端处理

1. 启用状态的普通用户只显示“停用”，停用状态的普通用户只显示反向操作“启用”；两个动作分别要求 `/app/user/disable` 和 `/app/user/enable` 精确权限。系统内置用户和当前登录用户均不显示启停操作。
2. 停用前显示二次确认，明确提示目标用户名、现有会话将全部失效且用户无法继续登录；首版不要求填写停用原因。启用前使用简单确认，提示不会修改密码或恢复旧会话。
3. 确认后提交目标用户 `id` 和列表当前 `revision`，提交期间禁止重复操作。成功后重新查询当前列表，不在前端直接改写行状态。
4. `revision` 冲突或目标状态已经变化时提示数据已更新并刷新列表，不自动重试状态变更。其他失败保留当前列表并显示脱敏业务原因。

### 后端协作与结果

启停资格、状态变化、会话与事务规则以[用户管理](../../domains/app.md#56-用户管理)为准。页面不乐观修改状态，始终以重新查询结果为准。

## `USR-05` 管理员重置用户密码

### 前端处理

1. 用户管理页只为启用状态的普通非本人用户提供“重置密码”操作，入口按新增动作在 OpenAPI 中登记的精确权限控制。停用用户、系统内置用户和当前登录用户不显示该操作；管理员必须先独立启用停用用户，才能再发起密码重置。
2. 操作前二次确认并明确提示目标用户名、原密码将立即失效、全部会话将被撤销，且目标用户下次登录必须修改临时密码。
3. 前端只提交目标用户标识和当前 `revision`，不生成或提交临时密码。提交期间禁止重复操作。
4. 成功响应返回后端生成的临时密码；前端只在本次成功结果中展示一次并提供复制操作，不写入本地存储、URL、日志、埋点或可再次查询的页面状态。结果关闭后无法重新查看，遗失时只能再次执行重置。
5. 一次性结果默认不能关闭；管理员勾选“已安全保存临时密码”后才启用关闭操作。结果关闭或离开页面时立即清除前端内存中的密码值，并重新查询用户列表。
6. 数据冲突时刷新列表并要求管理员重新发起操作；失败响应不得包含候选密码、密码摘要或内部错误。

### 后端协作与结果

重置资格、临时密码、会话撤销与事务规则以[用户管理](../../domains/app.md#56-用户管理)为准。页面仅消费本次成功响应，不推断或复现临时密码。

## 验收场景

- 没有 `/app/user/query` 时无法进入页面；
- 首次请求为第 1 页、每页 20 条、用户名升序；
- 关键词和状态只在用户明确查询或应用后生效，应用和重置回到第 1 页；
- 较早的慢响应不能覆盖较新的查询结果；
- 系统内置用户可见但没有编辑和启停动作；
- 列表及错误界面不暴露认证凭证或后端内部信息；
- 角色加载失败不能保存，停用角色和系统角色不能新选；
- 关闭已修改表单需要确认放弃，创建成功或确认放弃后清除密码和表单；
- 只有 `user/get` 时详情为只读，同时具备 `user/save` 和 `role/query` 后才可编辑；
- 编辑本人时角色只读；
- 停用角色保持可见且必须由管理员明确移除，不发生静默授权变更；
- `revision` 冲突不覆盖新数据，也不自动重放旧编辑；
- 系统内置用户和当前登录用户没有启停入口；
- 停用前有明确二次确认但不填写原因，成功后目标用户全部会话失效；
- 重新启用保留原密码和强制改密标记，不恢复停用前的任何会话；
- 系统内置用户和当前登录用户没有重置密码入口；
- 临时密码只在提交成功后展示一次，不进入持久化前端状态；
- 重置成功后页面刷新列表并提示目标用户下次登录完成强制改密；
- 停用用户必须先独立启用才能出现重置入口；
- 临时密码不按时间自动过期，一次性结果只有确认已安全保存后才能关闭。
