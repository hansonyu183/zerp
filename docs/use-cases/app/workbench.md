# 工作台用例

## 页面范围

- 路由：`/home/dashboard`
- 领域规则：[APP 工作台待办规则](../../domains/app.md)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [APP Schema](../../../contracts/openapi/schemas/app.yaml)
- 全站筛选和行操作规范：[前端工程约束](../../../frontend/AGENTS.md)

## `WKB-01` 打开工作台查看待办

### 入口与前端处理

1. 工作台是一级直接导航入口，不设置同名分组或二级菜单。
2. 页面默认进入“待办单据”，只查询当前页签，不同时加载“待办资料”。
3. “待办单据”和“待办资料”分别保存关键词、实体类型、待办阶段和分页状态。
4. 首次进入、每次切换到某个页签以及任一待办动作成功或失败后，前端都按该页签当前状态重新调用 `POST /app/workbench/query`，不得只展示首次加载的缓存结果。
5. 查询失败时显示明确错误和重新查询入口，不得把失败后的空结果显示为“暂无待办”。
6. 前端按响应中的 `availableActions` 渲染操作，不根据状态或本地权限推断额外动作。

### 后端协作与结果

后端按 APP 领域工作台规则从当前会话的最新权限推导实体范围，再与页面筛选取交集，生成待办并返回查询时点可执行的动作。用户执行动作时，对应 BOB/VOU 接口重新校验权限、revision 和业务状态；工作台查询结果本身不是后续动作的授权证据。

## `WKB-02` 筛选、查询和分页

### 前端处理

1. “待办单据”和“待办资料”分别保存关键词、实体类型、待办状态和页码，页签之间不共享或覆盖筛选状态。
2. 关键词输入后按回车或点击“查询”才发起请求；类型或待办状态发生变化后，点击“应用筛选”才发起请求，不使用输入或筛选变化自动触发的防抖查询。
3. 应用筛选和重置筛选都将当前页重置为第 1 页。查询失败时保留当前筛选条件，显示错误和重新查询入口。
4. 每页固定显示 20 条，不提供页面数量选择器。
5. 若并发处理导致当前页超过响应总数对应的最后一页，前端自动切换到新的最后一页并重新查询一次；总数为零时回到第 1 页并显示“暂无待办”，不得停留在页码有效但内容为空的过期页面。
6. 筛选区域的默认展开状态和行操作数量分流统一遵循前端工程约束，页面不自行实现响应式例外。

### 后端协作与结果

后端去除关键词首尾空白并限制为最多 128 个 Unicode 字符；实体筛选必须是合法且不重复的实体标识，待办状态只接受 `CHECK` 和 `APPROVE`。服务端先推导当前用户有权处理的实体范围，再与客户端实体筛选取交集，固定按更新时间倒序执行服务端分页。客户端筛选只能缩小结果，不能扩大权限范围。

## `WKB-03` 从待办行查看、编辑或处理

### 前端处理

1. 前端只展示后端 `availableActions` 返回的动作。同一行同时包含 `view` 和 `edit` 时只显示“编辑”，编辑页面本身承担查看内容并按权限修改的入口；没有 `edit` 时才显示“查看”。
2. 查看或编辑跳转到对应资料或单据页面，携带稳定的 `objectId` 或 `documentId` 以及 `view/edit` 模式；详情仍由目标页面通过所属领域 `get` 接口读取。
3. 提交、核对和批准在用户点击后直接调用对应领域动作，不增加二次确认。驳回和撤回提交必须先填写领域要求的意见或原因；反核对不要求原因，但必须先显示简单确认，明确单据将退回草稿。
4. 动作请求使用工作台行返回的稳定 ID、版本 ID 和 revision。前端不乐观修改本地状态；动作成功后按 `WKB-01` 重新查询当前页签并显示成功结果。
5. 动作失败时显示错误并重新查询当前页签。revision 冲突或状态已经变化时不得用响应中的最新 revision 自动重试，用户必须基于刷新后的状态重新判断并主动操作。
6. 操作排列遵循前端公共行操作模块：调用方提供按业务优先级排列的动作列表；不超过 3 个时全部直接显示，超过 3 个时前三个直接显示，其余进入“更多”。

### 后端协作与结果

工作台返回的 `availableActions` 只是查询时点快照。每个 BOB/VOU 动作仍重新校验有效会话、CSRF、精确动作权限、当前状态、稳定 ID、版本和 revision，并在所属领域事务中完成状态变化和审计。后端不得因为动作来自工作台而跳过领域校验，也不得接受客户端要求以最新 revision 自动重放已经冲突的动作。

## 验收场景

- 工作台在导航中可直接点击，不出现“工作台 → 工作台”二级结构；
- 首次只请求“待办单据”，首次切换再请求“待办资料”；
- 返回已加载页签时按其原筛选和分页重新查询；
- 动作成功或失败后重新查询当前页签；
- 查询失败显示错误和重试入口，不显示误导性的空态；
- 关键词和筛选条件只在用户明确查询或应用时请求后端；
- 应用或重置筛选回到第 1 页，每页固定 20 条；
- 并发变化使页码失效时自动回到新的最后一页，总数为零时回到第 1 页；
- 行操作只来自后端 `availableActions`，并遵循全站公共行操作组件的数量分流规则。
- 同时可查看和编辑时只显示“编辑”，只有不可编辑时才显示“查看”；
- 提交、核对和批准直接执行；驳回、撤回提交要求填写内容；反核对要求确认但不要求原因；
- 状态或 revision 冲突后刷新列表且不自动重试，用户基于最新状态重新操作。
