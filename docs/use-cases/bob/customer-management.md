# 客户管理

## 页面与依据

- 页面资源为 `bob/customer`，正式资料、提交记录与完整版本详情分开读取。
- 客户与全部子单位规则以 [BOB 客户](../../domains/bob.md#34-客户与客户子单位) 和 [Approval](../../domains/approval.md) 为准。
- HTTP 以 [BOB 提交与附件路由](../../../apps/api/src/bob/archive-contract.ts) 和 [正式资料、启停及引用路由](../../../apps/api/src/app/independent-contract.ts) 为准。

## `BOB-CUSTOMER-01` 正式资料与整体启停

有正式查询权限时进入页面加载一次，查询、翻页和写后刷新沿用全站列表规则。详情完整显示身份、开票、汇款识别及所有子单位资料。整体启停使用对象 revision；冲突刷新事实，失败保留当前展示。停用后新业务不可选，历史仍按采用版本展示。

## `BOB-CUSTOMER-02` 临时维护与提交

新建、克隆或变更只打开当前页面临时表单。新建默认身份沿用领域规则，根资料与子单位分区编辑。克隆分配新子单位身份且重新添加附件。选项按精确读取权限加载，已有采用值显示保存的名称。客户类型、结算、收款、运输定价、信用及归属完整提交；没有维护子单位权限时不能修改子单位。

提交失败保留输入，未知结果先按提交 ID 核实。关闭、刷新或账号切换清除临时输入，不持久化草稿。附件暂存、随提交入库和失败清理由同一客户资源完成。

## `BOB-CUSTOMER-03` 提交、审批与历史

提交记录与正式资料分别读取，生命周期动作只用服务端动作集和精确权限。历史展示完整根资料及子单位快照。正式引用阻止反批准时显示引用对象；不自动解除引用或回写历史。

## 验收

1. 完整维护两个子单位并提交、批准；正式资料和历史均保留身份税务、结算、信用、归属及附件。
2. 唯一启用子单位可隐式采用，两个启用子单位必须明确选择；多子单位收款保存实际分摊身份及版本。
3. 根资料变更保留子单位，子单位变更保留根资料；关闭表单再打开不恢复未提交输入。
4. 重复法定识别号失败整笔回滚；批准与整体停用并发不相互覆盖，精确引用阻止不安全反批准。
5. 旧客户及子单位 ID、历史 Approval Entry 和销售收款快照迁移后仍能准确读取，旧 DCL 客户入口不可调用。

## 动态版本档案交互（#410）

本资源从强类型 definition 经 Registry/Resource Host 装配统一版本档案页；页面生命周期、明细/详情/附件/历史区块及公开验收边界采用 [ADR-0060](../../adr/0060-dynamic-page-runtime.md)。上述业务用例在此真实入口验收，桌面和 390px 均覆盖，取消、未知写入、资源/Session 切换与迟到请求沿用全站规则。

附件区块在提交时暂存本地文件，展示进度与失败，可移除后重新选择；正式/候选/历史详情按 [附件路由](../../../apps/api/src/bob/archive-contract.ts) 的真实来源授权读取。克隆清除附件和原子单位身份；根资料变更保留无权维护的完整子单位，定价历史按子单位及规范化成本项名称显示新增、删除、金额及口径变化。
