# 客户用例

## 页面范围

- 路由：`/bob/customer`
- 客户关系、子账户、版本和权限规则：[BOB 领域](../../domains/bob.md)
- 订单、收款、开票和历史业务边界：[VOU 领域](../../domains/vou.md)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [BOB Schema](../../../contracts/openapi/schemas/bob.yaml)

本用例只定义客户页面如何编排领域动作和呈现结果。

## 新建

1. 用户先选择经营主体，再选择已有 Party 或填写新 Party，并在同一流程填写客户关系和首个结算子账户资料。
2. 强标识命中可见 Party 时，页面切换为复用；名称、电话、邮箱和地址的建议只显示当前用户可见项。命中不可见 Party 时，只显示联系管理员提示。
3. 从主体详情发起新增时，页面带入只读 Party；客户列表与主体详情共用同一创建动作和表单校验。
4. 成功后打开新客户详情并刷新列表。失败时保留输入、筛选和页面位置，显示后端业务消息及 `requestId`；失败结果不会在页面中留下可继续操作的新 Party 或客户关系。

## 详情与编辑

1. 详情分别呈现关系资料和用户可读取的 Party 投影；只有关系权限时，Party 字段保持受限只读。
2. 有待处理变更时，页面并列展示正在编辑资料和当前交易资料，并保留各自的版本标识与状态。
3. 编辑 Party 共享资料前展示后端给出的可见影响提示；保存成功后重新读取详情和列表。关系保存不顺带提交无权限编辑的 Party 字段。
4. 未保存输入关闭前要求确认。删除待处理变更须二次确认；成功后重新读取详情，失败时保留页面和输入。
5. Party 附件与关系附件分区展示和操作；历史详情只读，不提供写入动作。

## 列表与表单

1. 首次进入调用 `query`；关键词、状态、客户类型、经营主体和主要业务归属由公共筛选组件明确提交。列表展示编码、名称、客户类型、交易状态、启停状态和待处理变更标记。
2. 行操作按业务优先级提供查看、编辑与可用生命周期动作，并受后端返回的权限、状态和 revision 约束。
3. 表单按 Party 身份、客户关系、子账户、交易默认值、信用政策、定价、业务联系与附件分区。经营主体在创建后只读；编码由服务端生成。
4. 经营主体、客户类型、结算方式、收款方式、运输方式、业务归属和附件类别均使用最小候选投影。定价资料使用结构化字段编辑；信用额度展示 ACC 返回的实时占用。
5. 创建、保存和生命周期动作成功后重新读取详情和列表；后端拒绝时保留输入和当前页面。

## 读取、异常与恢复

1. 列表只使用 `query` 投影；查看、编辑和历史详情均重新调用 `get`。候选选择也使用独立最小投影。
2. 读取失败时展示后端业务消息和 `requestId`，保留筛选与页面位置并提供重试，不用列表行或本地默认值拼装详情。
3. revision 冲突时提示重新加载，允许用户复制未保存输入；引用候选在操作前失效时，展示对应字段错误并保留其他输入。

## 验收场景

1. 列表遵守全站显式筛选、固定分页、稳定排序、窄屏布局和行操作规则；详情总是重新读取。
2. 新建可复用可见 Party，也能处理不可见匹配；失败不会显示孤立的新记录。
3. 待处理变更与当前交易资料在详情和列表中清楚区分；删除待处理变更后恢复当前资料。
4. 创建、保存和生命周期动作遇到权限不足、候选失效或 revision 冲突时，页面不伪造成功，并保留可恢复输入。
5. 定价、信用额度和附件以各自页面控件呈现；历史资料保持只读。
