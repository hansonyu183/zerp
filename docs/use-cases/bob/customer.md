# 客户用例

## 页面范围

- 路由：`/bob/customer`
- 客户集团、结算子账户、版本生命周期、交易默认值、定价资料、附件及引用转移规则：[BOB 业务对象领域](../../domains/bob.md)
- 收款分摊、开票跟踪、订单快照及履约边界：[VOU 单据领域](../../domains/vou.md)
- 信用额度实时占用：[ACC 业务台账领域](../../domains/acc.md)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [BOB Schema](../../../contracts/openapi/schemas/bob.yaml)

本用例只记录客户页面的编排、状态和可观察结果，不重复上述领域文档中的业务规则。当前 OpenAPI 尚未提供的目标模型不构成已实现接口；实施时必须先同步契约，再接入前后端。

## 新建与跨实体资料复制

1. 新建客户先展示集团资料和首个结算子账户表单。集团填写非空税号后，页面请求后端检查用户有权读取的同税号供应商和其他往来单位；无税号时不发起模糊归户。
2. 命中来源时展示来源类型、编码和名称，并提供“忽略”和“复制资料”。未命中、用户忽略或后端允许独立创建时，继续使用当前输入建档。
3. 用户选择复制后，页面使用后端返回的可复制字段填充集团和首个子账户表单，仍允许在创建前编辑；页面不自行推断或复制来源对象的状态、版本及专属业务字段。
4. 来源检查失败不能显示成“未发现相同税号”。页面保留当前输入并提供重试或取消复制；是否允许继续独立创建以该次后端结果为准。

## 详情与编辑

1. 详情按客户精确权限决定只读或可编辑。存在候选版本时，同时展示“正在变更”和“当前交易使用”两套资料，不合并版本号、状态或 revision。
2. 保存成功后重新读取详情及列表投影，不在前端猜测版本、状态、快照或并发 revision。
3. 关闭存在未保存输入的表单前确认放弃；确认只清除前端输入，不删除已保存的候选版本。
4. 删除候选版本是独立高风险动作，必须二次确认并提交最新 revision。成功后重新显示有效版本；失败时保留页面和未保存输入。
5. 集团附件按集团 revision 独立维护；子账户候选版本展示后端复制的附件关联并允许增删或改类。历史和有效版本附件只读。

## 列表与筛选

1. 初次进入调用客户 `query`。筛选项包括关键词、状态、客户类型、默认经营主体、主要业务归属类型和归属主体；筛选提交、分页和稳定排序采用全站规则。
2. 列表展示编码、名称、客户类型、当前交易状态、启停状态和候选变更标记。存在候选版本时仍只显示一个客户行，候选状态使用独立标记。
3. 客户类型和主要业务归属显示中文类型及“编码 · 名称”；历史资料显示后端返回的版本快照名称。
4. 行操作按业务优先级提供查看、编辑及 BOB 生命周期动作，并统一服从精确权限、状态、revision 和全站行操作数量规则。

## 新建、保存与审核

1. 表单按集团资料、子账户基础资料、交易默认值、信用政策、定价资料、内部提示、联系资料和附件组织；客户编码只读且由服务端生成。
2. 经营主体、客户类型、结算方式、收款方式、运输方式、业务归属和附件类别均使用后端最小引用候选。选择结算方式或收款方式时只提交来源引用，由后端按领域规则保存客户快照，页面不拼装快照参数。
3. 定价资料使用结构化表单编辑两个顶层价格和具名成本行；页面按已知字段展示和校验，不提供原始 JSON 编辑器。
4. 信用额度按币种逐项编辑，页面展示 ACC 返回的实时占用，不自行计算或缓存。内部提醒和默认订单备注使用独立输入框并标明使用位置。
5. 创建成功后打开新客户详情并刷新列表。保存成功后用响应 revision 重新读取详情；失败时保留用户输入和当前页面。
6. 提交前页面检查必填输入，后端按 BOB 领域规则重新校验引用、快照、定价结构和 revision。提交、审核、驳回或撤回成功后均重新读取详情和列表。

## 启停、删除与历史

1. 禁用客户前二次确认。成功后刷新详情与列表；页面只展示后端返回的影响结果，不在前端推断交易是否还能继续。
2. 首版草稿和已有有效版本上的候选版本分别调用对应删除动作，并明确提示不可恢复。候选删除成功后重新显示最后有效版本。
3. 版本历史按版本号倒序，审核记录按发生时间倒序。定价策略使用结构化差异；BOB 关联批量转移产生的版本和审计显示原引用、接任对象、字段和操作者。
4. 历史详情只读，不提供保存、提交、审核、启停或删除动作。

## 页面读取边界

1. 客户列表调用 `query`，只取得列表投影；查看、编辑和打开历史版本均重新调用 `get`，不从列表行拼装详情。
2. 客户类型、经营主体、结算方式、收款方式、附件类别和业务归属主体使用独立最小引用投影，不复用实体详情。
3. 跨实体同税号检查使用专用后端动作，不能绕过来源实体查看权限，也不改变普通 `query` 与 `get` 的边界。

## 异常与恢复

1. 列表或详情读取失败时展示后端业务消息和 `requestId`，保留筛选和页面位置并提供重试；不得用旧列表行或本地默认值伪造详情。
2. revision 冲突时提示“客户已被其他人修改，请重新加载”，允许用户复制尚未保存的本地输入后刷新，不自动覆盖服务端数据。
3. 引用对象在选择后失效时，保存或提交展示后端返回的具体字段错误，重新加载对应候选并保留其他输入。

## 验收场景

1. 列表遵守全站显式筛选、固定分页、稳定排序、窄屏布局和行操作规则；打开详情必定重新调用 `get`。
2. 同税号来源检查成功时，用户可以忽略或复制有权查看的资料；失败时不会误显示为未命中，创建结果保持独立客户身份。
3. 存在候选版本时，列表仍只有一个客户行并显示候选标记；详情清楚区分候选资料与当前交易资料。
4. 创建、保存、提交和审核发生引用失效、权限不足或 revision 冲突时不产生部分更新，页面保留可恢复的输入上下文。
5. 删除候选版本后重新显示最后有效版本；删除失败或 revision 过期时页面和服务端数据均保持原状。
6. 定价资料只能通过结构化字段编辑，历史比较能指出各顶层金额和具名成本变化，不显示原始 JSON。
7. 集团附件操作刷新集团 revision；子账户候选附件变化不覆盖有效或历史版本附件。
8. 任何 BOB 关联批量转移后，客户详情、版本历史和审计显示新的当前引用，并保留原引用事实。
