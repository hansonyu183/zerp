# 其他单位页面用例

“其他单位”是 Party 与一个经营主体之间的 Service Relationship 页面。主体与关系的字段边界、唯一性和连续生效规则以 [BOB 领域规则](../../domains/bob.md) 为准，HTTP 请求和响应以 [OpenAPI](../../../contracts/openapi/openapi.yaml) 为准。

## 列表与详情

- 用户显式提交编码、主体名称、状态或经营主体筛选；列表固定每页 20 条并按业务编码稳定排序。
- 打开详情时调用 `POST /bob/other-unit/get` 读取权威版本；经营主体创建后只读。
- 页面只编辑业务联系人、业务联系方式、业务地址、可选结算方式和关系备注，不得修改 Party 身份字段。
- 关闭有未保存修改的表单时必须确认；窄屏下创建、编辑和生命周期动作完整可用。

## 新建与主体匹配

- 新建时可选择已有 Party，也可填写新 Party；两种入口都调用 `POST /bob/other-unit/create`。
- 名称模糊匹配只展示当前用户有权查询的非阻断建议；用户可一键切换为复用建议主体。
- 强标识在提交时精确匹配并自动复用。若命中无权读取的 Party，仅显示“主体已存在，请联系有权人员”，不得返回主体 ID、名称、字段或关系数量。
- 新 Party 与第一条其他单位关系在同一事务提交；关系失败时不得留下裸 Party。
- 同一 Party 与经营主体只能有一条其他单位关系。

## 生命周期与删除

- 首版按草稿、待审核、有效、停用流程处理；有效关系保存变更时创建候选草稿，旧有效版本继续可用。
- 候选撤回、驳回或删除不影响旧有效版本；候选通过后原子替换有效版本。
- 删除仍未触达正式历史的首条草稿时，若自动创建的 Party 没有其他关系、历史或引用，则在同一事务删除 Party；否则保留 Party。
- 页面和接口仅使用 `other-unit`；不存在 `other-party` 页面、路由、权限、别名或重定向。

## 验收场景

1. 新主体和首条关系创建成功后，两者均可读取；故意制造关系失败时两者均不存在。
2. 同一强标识再次创建会复用可见 Party；无读取权限时只得到通用错误。
3. 同一 Party、经营主体重复创建被拒绝；更改现有关系时不能提交新的经营主体。
4. 有效关系保存后列表同时表达当前有效版本和候选状态，删除候选后恢复只显示旧有效版本。
