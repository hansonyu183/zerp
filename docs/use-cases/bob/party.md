# 主体页面用例

主体页面只维护跨业务关系共享的身份事实。领域语义以 [BOB 领域规则](../../domains/bob.md) 为准，HTTP 请求和响应以 [OpenAPI](../../../contracts/openapi/openapi.yaml) 为准。

## 列表与详情

- 用户显式提交名称或主体类型筛选；列表固定每页 20 条，按稳定主体名称和 ID 排序。
- 页面不提供单独新增主体入口。主体只能在创建首条强类型关系时原子创建，或由后续关系复用。
- 打开详情时调用 `POST /bob/party/get` 读取权威数据，不使用列表行代替详情。
- 详情展示共享身份和后端按当前用户权限裁剪后的关系卡片；空卡片区不得暗示隐藏关系的类型或数量。

## 保存共享身份

- 仅具有 `/bob/party/save` 权限的用户可以修改主体类型、法定名称、显示名称、强标识、税号和通用联系方式。
- 保存前始终显示“会影响未来业务显示但不改变历史快照”的通用提示，并仅列出用户可见的关系卡片。
- 保存提交当前 `revision`；并发冲突保留本地表单，由用户重新读取后决定是否重做。
- 关闭有未保存修改的详情时必须确认；窄屏下全部身份字段、关系卡片和操作仍可访问。

## 合并重复主体

- 只有同时具有 `/bob/party/merge-preflight` 和 `/bob/party/merge-confirm` 两个精确权限的用户可以从主体详情发起合并；存在未保存身份修改时禁止进入合并。
- 当前详情主体固定为来源主体。用户按名称检索并明确选择同类型的保留主体，页面携带双方最新 `revision` 调用预检，不直接尝试执行合并。
- 预检阻断原因原样展示；每个同经营主体、同关系类型冲突都必须在来源关系与目标关系之间显式选择一个稳定关系 ID 保留，不提供默认选项。
- 预检通过后再次显示不可撤销确认。确认请求必须携带同一个 `preflightId`、双方 revision 和全部冲突选择；预检失效时保留页面上下文并要求重新预检。
- 成功后关闭来源主体详情并刷新列表；页面只展示转移关系数与合并冲突关系数，不宣称历史单据或 ACC 余额已经改写。

## 验收场景

1. 只有主体查询权限的用户能分页检索，但不能读取详情或保存。
2. 有主体详情权限但无其他单位详情权限的用户看不到其他单位关系卡片，也看不到隐藏数量。
3. 保存共享身份后列表和重新读取的详情立即更新，既有业务单据快照不变。
4. 页面上不存在主体生命周期、启停或单独新建操作。
5. 合并预检存在两个关系冲突时，漏选任一冲突都不能发送确认请求；来源或目标资料变化后，旧预检确认失败且不会发生部分合并。
