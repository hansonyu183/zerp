# 主体页面用例

主体页面只读取 DCL latest approved 形成的跨业务关系共享身份事实。领域语义以 [BOB 领域规则](../../domains/bob.md) 与 [DCL 主体申报](../../domains/dcl.md#35-主体申报) 为准，HTTP 请求和响应以 [OpenAPI](../../../contracts/openapi/openapi.yaml) 为准。

## 列表与详情

- 用户显式提交名称或主体类型筛选；列表固定每页 20 条，按稳定主体名称和 ID 排序。
- 页面不提供单独新增、保存、合并或审批入口。主体只能在创建首条强类型关系时原子创建，或由后续关系复用；共享身份维护与合并进入 `/dcl/party`。
- 打开详情时调用 `POST /bob/party/get` 读取权威数据，不使用列表行代替详情。
- 详情展示共享身份和后端按当前用户权限裁剪后的关系卡片；空卡片区不得暗示隐藏关系的类型或数量。

## 验收场景

1. 只有主体查询权限的用户能分页检索，但不能读取详情。
2. 有主体详情权限但无其他单位详情权限的用户看不到其他单位关系卡片，也看不到隐藏数量。
3. DCL Party candidate 未批准时，BOB 页面继续显示旧 current；批准或反批后重新读取才切换或消失，既有业务单据保持快照。
4. 页面上不存在主体生命周期、启停、单独新建、编辑或合并操作。
