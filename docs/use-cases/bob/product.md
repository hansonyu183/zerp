# 产品用例

## 页面范围

- 路由：`/bob/product`
- 产品类型、抽象基准单位、单位换算、默认包装规格与固定配方：[BOB 业务字段](../../domains/bob.md#21-业务字段)
- 版本生命周期与禁用 blocker：[BOB 生命周期](../../domains/bob.md#4-生命周期状态机)和[反向与启停](../../domains/bob.md#64-反向与启停)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [BOB Schema](../../../contracts/openapi/schemas/bob.yaml)

本用例只记录产品页面的编排、状态和可观察结果，不复制领域规则，也不讨论属于 VOU 销售订单行的实际交付规格。

## 新建与草稿保存

1. 新建产品先填写名称，并从当前启用的 AUX 产品类型中选择一项；编码由服务端生成。产品页面按所选类型绑定的系统行为模板展示对应字段，不根据类型名称或 ID 猜测行为。草稿允许暂缺默认包装规格、单位配置和自制成品固定配方，创建或保存成功后打开产品详情并重新读取服务端版本。
2. 创建和保存只检查已经填写的数据是否合法，不以草稿尚未完整为由拒绝保存。失败时保留用户输入和当前页面，并展示后端业务消息及 `requestId`。
3. 关闭存在未保存输入的表单前确认放弃；确认只清除前端输入，不删除已经保存的草稿或候选版本。

## 产品类型

1. 产品类型使用扁平选择列表；页面显示“编码 · 名称”，不提供父子树或多选标签。产品分类继续负责树形归集，两者不得合并展示成同一字段。
2. 产品类型详情可以修改名称和说明；类型一旦被任何产品版本引用，行为模板只读。需要另一行为模板时新建产品类型，不提供批量改写已有产品行为的操作。
3. 产品草稿和候选版本都可以改选另一当前启用的产品类型。同一行为模板内改选只替换类型引用；跨行为模板改选时，页面列出将被清除的固定配方、默认包装规格或包装物字段，用户确认后清除并重新执行统一检查。
4. 用户取消跨模板确认时保持原类型和全部输入。确认后允许开放版本暂时不完整；在该版本审核通过前，详情继续清楚区分正在变更的资料和当前交易使用的最新已批准版本。

## 单位配置

1. 单位配置随产品版本在产品表单内维护，不是独立业务对象、独立版本或独立页面。每个换算项选择一个 AUX 计量单位并填写大于零的定点换算系数，同一产品版本内单位不得重复。
2. 页面分别选择默认录入单位和计价单位；两者及页面提供的其他可选录入单位都必须存在于当前版本的换算项中。新增换算项后才能把该单位选为默认值或提供给后续录入页面使用。
3. 页面按“录入数量 × 换算系数”显示建议基准数量，并明确要求用户确认最终基准数量。单位换算只辅助录入，不把换算结果、换算系数或当前产品配置当作业务单据的权威数量。
4. 删除默认录入单位或计价单位对应的换算项时，页面明确提示并在确认后同时清空对应选择，使草稿进入待完善状态；不得留下指向不存在换算项的隐藏值。取消时保留原换算项和选择。
5. 修改换算系数只更新当前页面尚未确认的建议值，不重新计算已经保存的固定配方、已批准产品版本或任何 VOU 数量快照。

## 固定配方

1. 自制成品在产品表单内维护固定配方。基准产量可选择该成品版本已经配置的任一录入单位；每行原料用量可选择对应原料版本已经配置的任一录入单位，默认使用各自的默认录入单位。
2. 页面同时保存录入数量、单位审计快照和用户确认的基准数量。单位换算只计算建议基准数量；用户修改建议值后，以确认提交的基准数量为配方事实。
3. 从最新已批准产品编辑出新开放版本时，后端按原料对象自动把配方行更新到各原料的最新已批准版本，同时保持原有基准产量和基准用量不变。页面展示被更新的原料版本；原产品版本和历史订单保留保存时的配方内容。
4. 配方行只允许选择当前启用且存在最新已批准版本的原材料，同一原料不得重复；添加、删除、调整顺序或数量都随当前产品开放版本整体保存，不提供配方独立 API 或独立生命周期。
5. 自动更新原料时，如果原料已禁用或不存在最新已批准版本，仍创建产品草稿并把对应配方行标记为待处理。页面保留原料对象和原数量供修正，不自动删除；提交和审核必须阻止，直到用户改选或删除该行。
6. 原料版本自动更新后保持权威基准用量不变，按新原料版本的默认录入单位和换算生成新的建议录入数量。页面要求用户在提交前确认，新产品版本保存确认后的录入数量、单位审计快照和原有基准用量。

## 提交与审核检查

1. 产品页面在提交前调用统一的前端检查模块，一次检查产品当前类型要求的默认包装规格、单位配置和固定配方，并把问题定位到具体字段或明细行。
2. 审核入口复用同一检查结果展示方式；后端在提交和审核时重新执行完整业务校验。前端检查通过不构成后端放行依据。
3. 检查失败时停留在当前编辑上下文并保留输入；服务端返回引用失效、revision 冲突或其他业务错误时展示具体消息和 `requestId`，不得自动覆盖用户输入。

## 详情、列表与筛选

1. 初次进入调用产品 `query`。筛选项包括关键词、状态、产品类型和产品分类；筛选提交、分页和稳定排序采用全站规则。
2. 列表展示编码、名称、产品类型、默认录入单位、型号、当前交易状态、启停状态和开放版本变更标记。存在开放版本时仍只显示一个产品行，并继续将最新已批准版本作为新 VOU 的可选版本。
3. 打开查看、编辑或历史版本必须重新调用产品 `get`，不得从列表投影拼装详情。详情按基础资料、产品类型、单位配置、模板专属资料和备注分区展示。
4. 开放版本与最新已批准版本同时存在时，页面分别显示“正在变更”和“当前交易使用”；产品类型、行为模板、默认包装规格、单位换算和固定配方不得跨版本合并展示。

## 启停、删除与历史

1. 启用、禁用、删除首版草稿、删除候选版本、提交、撤回、审核、反审和驳回沿用统一 BOB 生命周期、权限、revision 和确认规则。
2. 产品禁用后阻止新的 VOU 引用；已有 VOU 继续使用自己的产品和数量快照。禁用冲突及解除方式直接采用 BOB 领域的统一启停规则。
3. 版本历史按版本号倒序，审核记录按发生时间倒序。历史详情只读，显示当时的产品类型、行为模板、单位配置、默认包装规格和固定配方，不按当前 AUX 或产品资料重新解释。

## 异常与恢复

1. 产品类型、产品分类、计量单位或配方原料在选择后失效时，保存已填写草稿可以保留数据；提交和审核展示后端返回的具体字段或明细行错误，并保留其他输入。
2. revision 冲突时提示“产品已被其他人修改，请重新加载”，允许用户复制尚未保存的输入后刷新，不自动覆盖服务端版本。
3. 列表、详情或候选项读取失败时展示后端业务消息和 `requestId`，保留筛选、页面位置和当前输入并提供重试；不得使用缓存或旧列表行伪造最新已批准资料。

## 验收场景

1. 业务用户可以新增多个绑定同一行为模板的产品类型；已被引用的类型不能修改行为模板，产品类型列表不出现父子层级或多选。
2. 产品跨行为模板改选类型时先展示将清除的数据；取消不改变输入，确认后候选可保存但必须补齐新模板要求才能提交和审核。
3. 默认录入单位、计价单位和其他可选单位都存在唯一换算项；删除被使用的换算项会同步清空选择，不留下隐藏引用。
4. 自制成品开放版本自动使用原料最新已批准版本；无可用版本的行保留为待处理并阻止提交，不删除原数量。
5. 新 VOU 只使用产品最新已批准版本并保存快照；开放版本、后续产品换版、类型停用或单位换算变化都不改写已有单据。
