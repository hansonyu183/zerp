# 供应商用例

## 页面范围

- 路由：`/bob/supplier`
- 供应关系字段、生命周期、引用转移和结算快照：[BOB 业务对象领域](../../domains/bob.md)
- 采购订单、采购入库、采购退货及结算日期：[VOU 单据领域](../../domains/vou.md)
- 供应商预付、应付和采购结算门槛：[ACC 业务台账领域](../../domains/acc.md)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [BOB Schema](../../../contracts/openapi/schemas/bob.yaml)

本用例只记录供应商页面的编排、状态和可观察结果。委托配制制造费等采购加价不属于供应商主数据，由对应专门采购单据维护和留存。

## 新建

1. 新建页先选择我方经营主体，再选择现有主体或在同一表单录入新主体，并展示供应关系资料、结算方式和默认采购员；新主体与首条供应关系必须原子创建，任一失败都不得留下裸主体。供应关系编码只读且由服务端生成。
2. 草稿允许暂缺结算方式和默认采购员，但提交和审核前必须补全。创建成功后打开新供应商详情并刷新列表。
3. 用户按强标识精确匹配主体；命中时必须复用。名称、电话、邮箱和地址只返回其有权读取的疑似主体并允许继续创建，页面不自行扩大查询范围。
4. 选择现有主体时复用其主体 ID，并在该主体与所选经营主体之间创建供应关系；页面不得复制主体资料另建供应商身份。未选择现有主体时必须在当前流程同时录入主体资料，不能先创建裸主体。
5. 强标识命中无权读取的主体时展示不泄露资料的联系管理员提示；其他创建或主体查找失败时保留用户输入和当前页面，展示后端业务消息及 `requestId`。
6. 从主体详情发起“新增供应关系”时，页面带入只读主体引用并继续要求选择经营主体；提交调用与供应商列表“新建供应关系”完全相同的关系创建动作，不维护第二套字段或校验规则。

## 列表与筛选

1. 初次进入调用供应商 `query`。筛选项包括关键词、状态、经营主体和默认采购员；筛选提交、分页和稳定排序采用全站规则。
2. 列表展示编码、名称、类型、当前交易状态、启停状态和候选变更标记。存在候选版本时仍只显示一个供应商行，业务摘要取最后有效版本，候选状态独立显示。
3. 经营主体和默认采购员显示中文类型及“编码 · 名称”；已知枚举不得回退显示协议原码。
4. 行操作按业务优先级提供查看、编辑及 BOB 生命周期动作，并统一服从精确权限、状态、revision 和全站行操作数量规则。

## 详情、编辑与审核

1. 详情按供应关系精确权限决定关系资料只读或可编辑，并按独立主体权限决定共享身份资料是否可编辑；只有供应关系权限时只显示允许的主体投影。存在候选版本时，同时展示“正在变更”和“当前交易使用”两套关系资料，不合并版本号、状态或 revision。
2. 修改主体共享资料前展示跨关系影响提示，只列出当前用户有权读取的关系；无法列出的关系不显示类型、数量或占位。确认保存后主体当前资料立即更新，供应关系历史和交易快照保持不变。
3. 表单分区维护主体名称、简称、税号和通用联系资料，以及供应关系业务联系资料、地址、备注、结算方式和默认采购员；主体身份字段与关系字段不得重复。缺少主体编辑权限时共享身份资料只读，保存供应关系不得提交这些字段。经营主体在创建供应关系时确定，编辑现有关系时只读；不提供制造费、委托配制能力或采购加价字段。
4. 选择结算方式时只提交来源引用，由后端保存供应商自足结算快照；页面不拼装到期参数，也不保存客户销售加价。
5. 默认采购员只引用当前有效员工，表示我方新采购订单的默认经办人，不表示供应商联系人。新采购订单可以改选并保存自己的采购员快照。
6. 保存成功后用响应 revision 重新读取详情；提交、审核、驳回或撤回成功后重新读取详情和列表。失败时保留用户输入和当前页面。
7. 有效供应商编辑时保留旧有效版本继续可采购，候选版本审核通过后原子切换。需要立即停止新采购时显式禁用供应商，不通过创建候选版本暗示停用。

## 启停、删除与历史

1. 禁用供应商前二次确认。后端返回当前 BOB 关联影响；存在必须转移的当前引用时，页面要求按领域规则选择同类型接任对象，不在前端猜测或部分执行。
2. 首版草稿和已有有效版本上的候选版本分别调用对应删除动作，并明确提示不可恢复。候选删除成功后重新显示最后有效版本。
3. 删除与新主体原子创建的首条供应关系草稿时，如果主体没有其他关系、历史或引用，后端在同一事务删除关系和主体；页面成功后返回列表，不保留或跳转到裸主体详情。
4. 版本历史按版本号倒序，审核记录按发生时间倒序；历史详情只读，不提供保存、提交、审核、启停或删除动作。

## 页面读取边界

1. 供应商列表调用 `query`，只取得列表投影；查看、编辑和打开历史版本均重新调用 `get`，不从列表行拼装详情。
2. 结算方式和默认采购员使用独立最小引用投影，不复用实体详情。引用列表加载失败时显示明确错误并阻止以空值提交或审核。

## 异常与恢复

1. 列表或详情读取失败时展示后端业务消息和 `requestId`，保留筛选和页面位置并提供重试；不得用旧列表行或本地默认值伪造详情。
2. revision 冲突时提示“供应商已被其他人修改，请重新加载”，允许用户复制尚未保存的本地输入后刷新，不自动覆盖服务端数据。
3. 结算方式或默认采购员在选择后失效时，保存、提交或审核展示后端返回的具体字段错误，重新加载对应候选并保留其他输入。

## 验收场景

1. 列表遵守全站显式筛选、固定分页、稳定排序、窄屏布局和行操作规则；打开详情必定重新调用 `get`。
2. 草稿可暂缺结算方式或默认采购员，但提交和审核均被后端拒绝；补全后保存自足结算快照并可审核生效。
3. 存在候选版本时，列表仍只有一个供应商行并显示候选标记；新采购继续引用旧有效版本，候选审核后才切换。
4. 删除候选版本后重新显示最后有效版本；删除失败或 revision 过期时页面和服务端数据均保持原状。
5. 同一主体可以同时拥有客户、供应或其他业务关系；新增供应关系复用主体身份，不复制主体资料或合并各关系生命周期。
6. 委托配制制造费等采购加价不会出现在供应商表单、版本或引用投影中，后续只由对应专门采购单据定义和保存。
