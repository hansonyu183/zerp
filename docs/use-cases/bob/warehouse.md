# 仓库用例

## 页面范围

- 路由：`/bob/warehouse`
- 仓库共享边界、负责人、连续生效和停用规则：[BOB 领域](../../domains/bob.md)
- 库存数量控制：[ACC 领域](../../domains/acc.md#9-库存数量账与控制)
- 使用仓库的业务单据：[VOU 领域](../../domains/vou.md)
- 线协议：[OpenAPI](../../../contracts/openapi/openapi.yaml) 与 [BOB Schema](../../../contracts/openapi/schemas/bob.yaml)

本用例只记录仓库页面的编排、状态、可观察结果和恢复方式，不复制库存余额或单据履约规则。

## 新建与保存

1. 新建仓库填写名称，以及可选的仓库负责人、地址、联系人、联系电话和备注；编码由服务端生成。仓库不选择经营主体、库区、库位、储罐或库存核算账簿。
2. 仓库负责人从当前有效雇佣关系中选择，页面名称固定为“仓库负责人”。该字段可空，只用于联系与责任展示，不产生仓库操作权限。
3. 创建或保存成功后打开服务端返回的详情并刷新列表。失败时保留输入和页面位置，展示业务消息及 `requestId`。
4. 关闭存在未保存输入的表单前确认放弃；确认只清除前端输入，不删除已经保存的首版草稿或候选版本。

## 列表与详情

1. 初次进入调用仓库 `query`；关键词、状态和启停筛选由用户明确提交，分页与稳定排序采用全站规则。
2. 列表展示编码、名称、地址、联系人、当前交易状态、启停状态和候选变更标记。查看、编辑和历史详情均重新调用仓库 `get`，不从列表投影拼装详情。
3. 有候选版本时列表仍只显示一个仓库，并以最后有效版本作为当前库存业务资料；详情分别展示“正在变更”和“当前业务使用”。
4. 行动作按精确 APP 权限和服务端当前状态显示。负责人身份不增加、减少或替代任何页面及仓库操作权限。

## 变更、负责人失效与恢复

1. 编辑已生效仓库时创建连续生效候选版本；候选待审、撤回或驳回期间，旧有效版本继续供出入库、生产、退货和盘点使用，审核成功后原子切换。
2. 负责人对应员工仍被当前有效仓库引用时，员工停用返回包含仓库负责人引用数量的结构化 blocker，员工和仓库均保持不变。
3. 用户进入仓库的正常编辑流程，清空或更换负责人，完成提交和审核后再停用原员工。页面不得自动覆盖候选草稿或为仓库直接创建有效版本。
4. revision 冲突时提示仓库已被其他人修改，允许用户复制未保存输入后重新加载；不得自动覆盖服务端版本。

## 启停与删除

1. 用户点击停用后，页面只展示普通确认，不发起预检请求；确认后直接调用仓库 `disable`。
2. `disable` 按 [BOB 领域的仓库停用规则](../../domains/bob.md#44-对象启停)执行。存在阻断时页面根据错误 `data` 中的 `inventory`、`documents`、`sources`、`references` 展示冲突摘要，保留 `requestId`，仓库保持启用。
3. 停用成功后，仓库不再进入新的业务选择；已批准历史单据和库存流水不受影响。重新启用后才恢复新的仓库引用。
4. 删除首版草稿、删除候选版本、提交、撤回、审核、反审和驳回沿用统一 BOB 生命周期、revision、确认及审计规则。

## 验收场景

1. 不同经营主体的业务可以选择同一仓库，库存按产品和仓库共同核算；页面和单据都不出现经营主体库存子账或仓库内位置。
2. 仓库资料候选待审期间，旧有效仓库仍可被新库存业务引用；列表不出现两个仓库行，也不把候选资料当成当前业务事实。
3. 仓库负责人为空不阻止提交、审核或业务引用，也不改变任何用户权限。
4. 员工仍是任一当前有效仓库的负责人时停用失败，并且不清空负责人、不新建仓库版本、不覆盖候选草稿。
5. 只有零库存、没有待处理单据、没有仍可产生库存动作的来源单据且没有当前有效 BOB 引用时才能停用仓库；并发新增阻断会使停用失败且不产生部分状态变化。
