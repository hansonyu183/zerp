# 客户变更用例

## 页面范围

- 路由：`/dcl/customer`
- 领域规则：[DCL 客户申报](../../domains/dcl.md#361-客户与客户核算账户申报)、[BOB 客户边界](../../domains/bob.md#2-领域职责与边界)

本页是 Customer 及其全部客户核算账户唯一维护入口。不存在 Party 页面、独立客户核算账户页面、账户审批任务或账户版本历史。

## 创建与整体保存

1. 新建录入客户身份、税务、汇款识别、默认经营主体、身份税务附件及至少一个核算账户，并指定默认账户；原子性采用 [DCL 客户申报](../../domains/dcl.md#361-客户与客户核算账户申报)。
2. 核算账户编辑器维护稳定 `accountId`、客户内唯一 code、名称、联系人、业务地址、客户类型、结算、收款、运输、定价、信用额度、业务归属、内部提醒、订单默认值、业务附件与 `enabled`。
3. 页面一次提交客户及全部账户的完整表单；任一账户新增、修改、停用或移除都修改 Customer candidate，不调用账户级保存接口。
4. 客户不维护可交易经营主体名单；默认经营主体只用于单据预填。账户业务参数跨经营主体共用一套默认值。

## 生命周期与删除

1. 页面编排 Customer 的 `query|get|create|save|submit|unsubmit|reject|approve|unapprove|delete|versions|audit-history`，并只展示服务端 `availableApprovalActions`。
2. `DRAFT` 显示“编辑草稿”；已批准且无候选显示“发起变更”；存在可编辑候选显示“继续编辑草稿”；不可编辑状态只显示“查看”。
3. Customer candidate 未批准时 BOB 和交易继续使用上一正式完整版本；批准后客户及全部账户一次切换。
4. 草稿删除、正式账户移除和历史读取直接采用 [DCL 客户申报规则](../../domains/dcl.md#361-客户与客户核算账户申报)；页面只展示服务端结果和 blocker。

## 验收场景

1. 创建、一次保存和一次批准原子覆盖客户及全部账户；失败不留下部分账户或附件。
2. 客户强标识只在 Customer 类型内唯一；跨 Supplier 等类型不比较或合并。
3. 列表和工作台只有一个 Customer 工作项；账户行没有独立编辑、审批、版本或审计动作。
4. 反批准 blocker 和历史结果采用 DCL 领域规则，页面不得自动迁移账户或改写业务事实。
