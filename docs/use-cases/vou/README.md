# VOU 页面公共用例

## 范围

- 36 个原子单据各自拥有 `/vou/{entity}` 页面；业务规则以 [VOU 领域文档](../../domains/vou.md) 为准，wire 结构以 `apps/api/src/vou/contract.ts` 的可执行 Hono/Zod 路由为准。
- 页面不根据字段描述器动态生成技术表单。描述器只在测试中核对每个实体的 payload 字段都被一个明确业务家族负责；运行时由定价、订单、履约、生产库存、资金、费用、资产、票据、居间和服务编辑器提供中文交互。

## `VOU-COMMON-01` 查询与详情

1. 页面显式调用对应实体 `query`，固定每页 20 条，支持关键字、审批状态、业务日期、往来对象与单项排序；迟到的旧响应不能覆盖新查询。
2. 列表与详情采用服务器返回的 Submission、revision、payload、`availableApprovalActions` 和 `canDelete`；页面不从本地状态推导审批动作。
3. 详情显示 Submission 保存的业务日期、币种、引用和业务明细快照，不回查当前主数据覆盖历史事实。
4. 工作台可用 `documentId` 与 `mode=view|edit` 深链打开详情；同一路由内 query 变化和浏览器前后退必须同步关闭或切换详情，迟到请求不得覆盖当前路由。`mode=edit` 只在详情为服务器当前批准版本且用户拥有变更权限时创建本地 Draft。

## `VOU-COMMON-02` 本地 Draft 与提交

1. 可人工创建的 32 个实体在当前用户、当前浏览器空间保存本地 Draft；新建、变更与删除本地 Draft 不创建或删除服务器单据。
2. 提交前保存当前 Draft；成功只删除本次 Draft 并刷新列表，失败保留原 Draft。新增与变更分别调用对应 `submit-new`、`submit-change`。
3. 引用由具名选择器产生，不允许用户手输 Approval Entry；数量和金额使用十进制字符串，产品行同时呈现录入数量、单位和基础数量。
4. 销售出库、销售送货、销售签收、费用付款四类由系统生成，页面不出现新建、克隆或提交入口，只提供查询、详情与服务器允许的审批动作。
5. 销售退货、采购入库、采购退货和生产配货通过 `POST /vou/source-line/query` 选择来源行；服务器按目标实体限定合法上游链，并返回来源单号、业务日期、产品标签和扣除当前占用后的可用基准数量。页面不得根据全量单据自行推断来源资格或剩余量，也不得要求用户输入技术行 ID。

## `VOU-COMMON-03` 生命周期

1. `approve`、`reject`、`unreject`、`unapprove` 只按详情返回的动作呈现；驳回与反批准必须填写原因。
2. 开放 Submission 只有在服务器返回 `canDelete` 时才显示撤回；revision 冲突后刷新服务器事实，不自动重放动作。
3. 状态、编号、附件、引用有效性、库存、资金和下游 blocker 均由服务端事务重验，前端只显示稳定 `errorKey` 对应的用户说明。

## 当前契约缺口

1. 权威领域要求销售订单和采购订单冻结结算、联系人、地址及订单特有的定价/信用/履约快照；当前共享 model/Hono payload 只覆盖现有引用、产品行和少量控制字段，页面不得伪造缺失事实，也不能宣称贸易订单领域已完整恢复。
2. 权威领域要求订单列表展示履约数量摘要；当前 VOU query/get view 尚未返回这些汇总。
3. 正式页面已接线浏览器本地草稿附件、提交前暂存及 Submission 附件下载；审计时间线仍未在页面展示。

## 验收

1. typed config、页面组件 registry 与 shared model 都精确覆盖 36 个实体，且只允许 32 个实体创建本地 Draft。
2. 运行时页面源代码不遍历 `vouEntityInputDescriptors` 构造表单，不出现 JSON payload 编辑器。
3. 刷新后本地 Draft 可恢复，不同用户隔离；服务器动作与只读系统生成限制不可由前端绕过。
