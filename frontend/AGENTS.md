# ZERP 前端工程约束

## 模块职责

- 本模块位于 `frontend/`，共享契约、领域文档、运行环境和全仓门禁以根目录 `AGENTS.md`、`README.md` 为准。
- 纯前端任务默认只修改 `frontend/`；跨端契约任务按根规则同时修改 OpenAPI、后端适配、前端调用和测试。

## 工程约定

- 技术栈为 Vue 3、TypeScript、Vite、Vuetify 和 Pinia；使用根目录锁定的 Node.js 与 pnpm 版本。
- 页面组件负责模板、样式和交互装配；业务状态与动作放在同目录的 `vm.ts`。仅跨页面共享且需要保持一致的状态进入 Pinia。
- 模块按最小有效共享范围归属：跨领域且无业务语义、无 API 调用的 UI 原语放入 `src/components/common/`；跨页面复用的领域或业务能力组件放入 `src/components/{feature}/`；只服务同一领域页面的工作区、ViewModel、配置和业务辅助逻辑放入 `src/pages/{domain}/shared/`；实体专属实现保留在 `src/pages/{domain}/{entity}/`。
- 可复用的有状态行为放入 `src/composables/`，纯映射、状态文案、权限计算和数据转换使用独立模块。页面不得直接请求 API 或解析响应；`vm.ts` 是页面状态和动作的编排入口，可调用同目录模块和 composable。
- 公共抽取应已有两个及以上实际调用点，或存在已经确认的跨页面一致性需求。不得为改名创建薄包装，也不得复制公共实现后只做轻微分叉；同类 CRUD 页面优先通过配置和插槽复用现有列表、编辑器及交互壳层。
- 页面中的独立工具栏、弹窗、权限判断和数据转换应按职责拆分，避免页面模板同时承担请求、业务转换和动作编排。差异化组件必须由明确业务语义驱动，而不是由页面路径驱动。
- 异步搜索和远程候选加载必须防止旧请求覆盖新结果，并在候选刷新或分页后保留当前已选引用；组件销毁后不得继续写入页面状态。
- 中文 UI 文案优先使用自然、明确的短词。表格列名必须省略页面上下文中重复的实体前缀，并在不产生歧义的前提下使用最短表达；同表相似字段保留必要的业务区分词，不使用生造缩写。表单、筛选和校验文案以明确性为先，不强制套用表格短标题。
- 客户、供应商、产品、仓库等对象引用下拉的候选项、已选值和只读详情统一显示为“编码 · 名称”；状态、类型等枚举只显示业务文案，没有名称属性的单据引用只显示单号等业务标识。
- 宽度不超过 700px 的手机界面中，展示表格和输入表格必须转为纵向卡片并保留字段标签、排序和行操作，不得依赖横向滚动；列表操作默认使用“主操作 + 更多菜单”，破坏性和低频操作放入更多菜单。
- 新增或调整页面时，应优先复用公共组件，精减重复元素，并为同类任务提供统一的交互方式和 UI 风格；确需差异化时必须由明确的业务语义驱动。
- 所有表格表头统一使用主题化底色；可排序列必须复用公共排序表头或 Vuetify 数据表原生排序能力，在列名右侧显示小型排序图标，不得使用独立按钮外观。
- 表格单元格内的文本、选择和引用输入统一使用紧凑的无外框单下划线样式，并复用公共表格输入组件；筛选区和普通表单不受此规则影响。
- 所有对象和单据的编码由系统自动生成，新增界面不得要求用户手工输入；仅后端需要的兼容字段不得通过“更多设置”等入口重新暴露到 UI。
- 业务 API 只能通过 `src/api/client.ts` 及领域封装调用生成客户端；不得直接使用 `fetch`、任意字符串路径、假数据或失败兜底数据。
- Cookie 会话和 CSRF 统一由 API 客户端处理。认证与权限使用 `app` 领域标识，不使用 `auth`。
- 除 `app` 领域外，后端返回的任一有效实体权限都可生成菜单；本地已注册实体加载对应页面，未注册实体只能加载前端固定的“开发中...”占位页。权限数据不得指定组件路径。前端权限仅用于菜单、按钮和交互控制，后端鉴权才是最终安全边界。
- Vitest 单元及组件测试可使用 MSW；Playwright 核心流程必须连接真实测试后端，不得拦截或模拟业务请求。
- 结构重构后，覆盖率门禁应随职责迁移到新模块并为新模块补充测试；不得仅通过降低整体阈值掩盖覆盖流失。并发查询 composable 必须覆盖旧响应失效和已选值保留等关键分支。
- 修改后至少运行相关单元测试，开发期按需运行 `pnpm build`。关键业务流程变更必须补充对应测试；形成可验收提交后按根规则运行 `make pre-push`。
